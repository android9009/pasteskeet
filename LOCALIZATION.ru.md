# Языки меню и локализация через Lua

Язык и шрифт настраиваются независимо. Можно оставить стандартный язык и поменять
только шрифт, создать свой язык без шрифта или задать своему языку собственный шрифт.
Отдельные Lua-окна с клавишами открытия описаны в [WINDOWS.ru.md](WINDOWS.ru.md).

В конце левой колонки **Misc**, после **Custom Scope**, в **Language** доступны **English** (по умолчанию)
и **简体中文** (упрощённый китайский). Перевод охватывает функции меню, параметры, списки
выбора, контекстные меню биндов/цветов, Config и кнопки редактора Lua.
В NEXT GEN также переведены вкладки и их группы, заголовки блоков, Save,
информация о версии и подписке, Style, поиск, статусы конфигов/скриптов и вопросы
подтверждения. В CLASSIC переключатель Style расположен сразу под Language.
Язык применяется со следующего кадра и сохраняется вместе с конфигом
в настройке `misc / menu language` как строковый ID.

Перевод меняет отображаемый текст. Идентификаторы элементов, ключи конфигов,
имена в `settings.get/set`, индексы combo и код в редакторе сохраняются.
Подписи и варианты выбора `ui.create`, текст из `render.text`, код, вывод и логи
Lua-скриптов не переводятся, даже если совпадают с ключами словаря (например,
`Enabled`, `Head` или `Color`). Скрипт сам выбирает язык своих элементов:
английский или любой другой. Введённый текст тоже не переводится.
Названия ресурсов из игры, отсутствующие в словаре, отображаются в исходном виде.
Изображения и фон не изменяются.

Китайские символы встроенного меню рисуются встроенным шрифтом **Skeet Menu CJK**
(подмножество Noto Sans CJK SC, SIL OFL 1.1). Все символы китайского меню и
названия 简体中文 включены в DLL; установка шрифтов Windows для них не требуется.
Для дополнительных символов пользовательских локализаций остаются системные
fallback-шрифты. Из TTC-коллекций читается полный файл с корректными смещениями.
Исходник, лицензия и офлайн-проверки: [шрифт меню](../../skeet/project/core/resources/fonts/menu_cjk.README.md).

## Собственный язык

Сохрани скрипт в UTF-8 и включи его в Config. Его язык появится в том же combo.
Полный тестовый перевод на бразильский португальский:
[menu_localization_pt_br.lua](examples/menu_localization_pt_br.lua).
Скопируй файл непосредственно в `%LOCALAPPDATA%\skeet`, обнови список Config
и включи его после ручной сборки проекта.
При включении он регистрирует **Português (Brasil)** с ID `pt-BR` и сразу
переключает основной интерфейс. Можно выбрать English или 简体中文 обратно в Misc.
Собственные тестовые элементы этого скрипта `Enabled`, `Hitboxes`, `Head`, `Chest`
остаются английскими, а `Minha opção` остаётся португальским.
Готовый китайский словарь, который можно использовать как список строк:
[menu-localization.zh-CN.json](menu-localization.zh-CN.json).

```lua
local ok = ui.register_language("my-language", "Мой язык", {
    ["Language"] = "Язык",
    ["Enabled"] = "Включено",
    ["Head"] = "Голова",
    ["Min Damage"] = "Минимальный урон",
    ["Save"] = "Сохранить",
})
if ok then
    ui.set_language("my-language")
end
```

Ключ — точный английский видимый текст, с учётом регистра, без `##` и скрытого
суффикса. Например, для `Color##scope` и `Color##tracer` ключ один: `Color`.
Словарь переводит основной интерфейс Skeet, включая окно редактора Lua.
Он не применяется автоматически к элементам Lua. Перевод отсутствующего ключа
возвращает исходную строку. Частичный пользовательский словарь дополняется
английскими строками. `ui.translate` — явный запрос перевода строки; автор
может вызвать его самостоятельно, но создание `ui.create` не вызывает перевод.

Словарь принадлежит скрипту. Повторная регистрация его ID тем же скриптом
полностью заменяет словарь и имя. Другой скрипт не может занять этот ID;
`en` и `zh-CN` зарезервированы. При выгрузке или ошибке скрипта его языки
удаляются. Если выбранный язык недоступен, меню показывает English, сохраняя
выбранный ID: после повторной регистрации перевод вернётся автоматически.
Для автоматического восстановления включи скрипт и сохрани конфиг.

## Шрифт меню и своего языка

Для смены **только шрифта** регистрация языка и `ui.set_language` не нужны:

```lua
local ok, reason = ui.set_menu_font("my_font.ttf", 11)
if not ok then client.log("Cannot set menu font:", reason) end
-- Release this script's default override:
-- ui.set_menu_font(nil)
```

Это работает и с English, и с 简体中文, и с пользовательским языком без отдельной
привязки шрифта. Выбранный язык не меняется. Готовый пример:
[menu_font_only.lua](examples/menu_font_only.lua).

Для **своего языка без смены шрифта** достаточно `ui.register_language` и
`ui.set_language`. Любые названия и переводы — UTF-8: например, японский,
таджикский или другой язык. Частичный словарь сохраняет английский fallback:

```lua
ui.register_language("ja-example", "日本語", {
    ["Language"] = "言語", ["Enabled"] = "有効", ["Color"] = "色",
})
ui.set_language("ja-example")
```

Для **своего языка со своим шрифтом** добавь после регистрации:

```lua
local ok, reason = ui.set_language_font("ja-example", "japanese.ttf", 11)
if not ok then client.log("Cannot set language font:", reason) end
```

Выбирай шрифт с символами нужного языка. Встроенный набор гарантирует покрытие
китайского меню; дополнительные языки используют глифы своего/системного шрифта.

Положи свой файл `.ttf`, `.otf`, `.ttc` или `.otc` непосредственно в
`%LOCALAPPDATA%\skeet` — в ту же папку, где лежат Lua. После регистрации языка:

```lua
local ok, reason = ui.set_language_font("my-language", "my_font.ttf", 11)
if not ok then
    client.log("Cannot set menu font:", reason)
end
-- Release the language font (use the menu override or normal font):
-- ui.set_language_font("my-language", nil)
```

Указывается только имя файла, без полного пути и подпапок. Размер по умолчанию
11 px, допустимо 8–24 px. Один выбранный размер применяется ко всему основному
интерфейсу, включая меню, popup и оболочку редактора. Подписи, варианты выбора,
код и логи Lua сохраняют собственные шрифты. Недостающие символы пользовательского
шрифта рисуются стандартным шрифтом Skeet и его CJK-fallback.

Привязку `ui.set_language_font` меняет владелец пользовательского языка.
Для стандартного языка используй `ui.set_menu_font`: создавать копии English
или 简体中文 не требуется. Словари встроенных языков и чужие привязки сохраняются.
Приоритет: шрифт выбранного языка → последний общий шрифт живого Lua-скрипта →
стандартный шрифт Skeet. `ui.get_menu_font()` показывает действующий выбор и его источник.
При выгрузке скрипта общий override удаляется, открывая предыдущую действующую привязку.

Файл проверяется сразу на CPU. GPU-ресурсы создаются при следующем отображении
меню в потоке рендера; если это не удалось, остаётся стандартный шрифт.
Вызывать назначение лучше один раз при загрузке Lua. При замене файла на диске
повтори вызов или перезагрузи скрипт: автоматического наблюдения за файлом нет.
Повторная регистрация словаря того же ID сохраняет назначенный шрифт. При
выгрузке/ошибке Lua привязка удаляется вместе с языком; следующий запуск скрипта
восстанавливает её. Шрифт отдельно в `.cfg` не записывается.

Лимиты: файл 1 байт–32 MiB; до 8 разных комбинаций байтов шрифта и размера,
до 64 MiB исходных байтов на весь runtime. Кэш сохраняется между перезагрузками
скриптов, чтобы готовые команды отрисовки не ссылались на освобождённые ресурсы.
Одинаковые байты и размер используют одну запись. Для TTC/OTC выбирается первый face.

Ошибки возвращаются как `false, reason`: `language_not_owned`,
`unsupported_font_extension`, `config_directory_unavailable`,
`resource_directory_unavailable`, `file_not_found`, `file_open_failed`,
`file_info_failed`, `file_size_limit`, `file_read_failed`, `font_load_failed`,
`menu_font_limit`, `menu_font_bytes_limit`. Неверные типы, размер вне диапазона,
неверный UTF-8, путь вместо basename или reparse point вызывают Lua-ошибку.
При отказе предыдущая привязка остаётся действующей.

Тестовый `menu_localization_pt_br.lua` использует `menu_pt_br.otf` из этой папки.
Для своей проверки замени имя в его вызове `ui.set_language_font`. Если файла нет,
пример выводит причину и работает со стандартным шрифтом.
На старой сборке без `ui.set_language_font` пример тоже сохраняет перевод,
используя стандартный шрифт; пользовательский шрифт появится после новой сборки.

## API

Эти функции доступны при загрузке и из callbacks; `paint` для них не требуется.

| Вызов | Результат |
| --- | --- |
| `ui.register_language(id, name, translations)` | `boolean`: регистрация/замена своего словаря |
| `ui.unregister_language(id)` | `boolean`: удаление своего словаря; чужие и встроенные не удаляются |
| `ui.set_language_font(id, filename?, size?)` | `boolean, string?`: файл шрифта для своего языка; `nil` сбрасывает привязку |
| `ui.set_menu_font(filename?, size?)` | `boolean, string?`: общий шрифт без смены языка; `nil` снимает override своего скрипта |
| `ui.get_menu_font()` | `{language, source, filename?, size?}`: эффективный шрифт и источник |
| `ui.get_language()` | Строка: эффективный ID, `en` при недоступном выбранном языке |
| `ui.set_language(id)` | `boolean`: выбор зарегистрированного языка; неизвестный ID не меняет выбор |
| `ui.translate(text, id?)` | Строка: перевод; без ID используется язык меню; неизвестный ID/ключ возвращает исходный текст |
| `ui.get_translation_keys()` | Массив точных английских ключей встроенного меню, отсортированный по ключу |
| `ui.get_languages()` | Массив `{id=string, name=string, font?=string, font_size?=number}`: English, китайский, затем пользовательские ID по алфавиту |

Для полного шаблона словаря:

```lua
for _, key in ipairs(ui.get_translation_keys()) do
    client.log(key, "=", ui.translate(key, "zh-CN"))
end
```

Ограничения: ID — 1–48 ASCII-байт (`A-Z`, `a-z`, `0-9`, `-`, `_`);
имя — 1–96 байт UTF-8; ключ — 1–256 байт UTF-8 без `##`;
перевод — 1–4096 байт UTF-8. NUL и неверный UTF-8 запрещены.
До 2048 записей и 128 KiB суммарных байт ключей/значений на словарь,
16 пользовательских языков на скрипт, 64 на все скрипты.
Неверные аргументы вызывают Lua-ошибку; занятый ID или лимит языков возвращает
`false`. Пустой словарь допустим и отображает английский текст.

## Проверка после ручной сборки

1. В новом конфиге убедись, что выбран English. Выбери 简体中文 и проверь все
   вкладки, открытые popup, списки Hitboxes, бинды и Config.
2. Сохрани конфиг, переключи язык, загрузи конфиг: выбор должен восстановиться.
3. Включи пример pt-BR: основной интерфейс должен стать португальским, а его
   собственные `Enabled`, `Hitboxes` и открытый список `Head`, `Chest` — остаться
   английскими. `Minha opção` остаётся португальским и при выборе 简体中文.
   Выгрузи и снова включи скрипт: язык должен исчезнуть и вернуться.
4. Проверь `ui.set_language("unknown") == false`, защиту встроенных ID и чужого
   словаря, а также замену словаря тем же владельцем.
5. Проверь длинные переводы: обрезка не должна разрывать UTF-8-символы.
   Ввод имени конфига, исходный код Lua и сообщения скрипта в Console должны
   оставаться буквальными. Проверь также popup элементов Lua после смены языка.
6. Назначь pt-BR другой локальный шрифт, проверь menu/editor/popup, затем сбрось
   его через `nil`. Назначение отсутствующего или испорченного файла должно
   вернуть ошибку, сохранив предыдущий шрифт. Переключение на English/简体中文
   возвращает их обычные шрифты, если общий override не задан; собственные элементы Lua не меняются.
7. На English назначь общий шрифт без регистрации языка: `ui.get_language()`
   должен остаться `en`. Переключи на 简体中文: общий шрифт действует и здесь.
   Выбери язык со своим шрифтом — он имеет приоритет; сбрось его и проверь общий fallback.

Проверка исходников без сборки: `python -B tools/verify_menu_localization.py`.
Она не подтверждает компиляцию или отображение шрифтов в игре.
