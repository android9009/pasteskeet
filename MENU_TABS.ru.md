# Свои вкладки меню и цвета букв SKEET

Пример: [rgb_menu_tab.lua](examples/rgb_menu_tab.lua). Скопируй его как отдельный
`.lua` в `%LOCALAPPDATA%\skeet`, обнови список скриптов и включи через обычное
подтверждение запуска. Нужна новая пользовательская сборка DLL с этим API.

В NEXT GEN кнопка **RGB Lab** появится слева сразу под **Scripts**, наравне с
нативными кнопками. **В основном меню отображаются максимум четыре Lua-вкладки
суммарно для всех скриптов.** Видны первые четыре по порядку создания; пятая и
следующие скрыты. Скрипты продолжают работать, а их настройки остаются доступны
на странице скрипта. Когда видимая вкладка удаляется/выгружается, её место
занимает следующая зарегистрированная. Это лимит кнопок, а не работающих Lua;
один скрипт с несколькими вкладками занимает несколько мест.

**CLASSIC не поддерживает добавление разделов/вкладок в основное меню.**
Настройки скрипта доступны через его обычную страницу, отдельные Lua-окна
продолжают работать в обоих стилях.

**Рекомендуется делать основные настройки в самой Lua, на её странице в Scripts,
а отдельную вкладку использовать дополнительно для более красивой визуализации.**
Она не должна быть единственным способом настройки: в CLASSIC её нет, а в
NEXT GEN она может не попасть в первые четыре. `ui.create` без привязки сохраняет
обычное размещение; `ui.attach_tab` добавляет представление того же контрола
во вкладке, сохраняя его на странице скрипта и общие значения/бинды.

## Создание вкладки и блоков

```lua
local tab = ui.create_tab("tools", "My tools", {icon = "T"})
local group = ui.create_tab_group(tab, "main", "My functions", 1)
local enabled = ui.create("checkbox", "my_enabled", "Enabled", true)
local amount = ui.create("slider", "my_amount", "Amount", 25, 0, 100)
ui.attach_tab(enabled, tab, group)
ui.attach_tab(amount, tab, group)
```

`ui.create_tab(id, title, options?)` возвращает свой `id`. Он локален скрипту:
два скрипта могут выбрать одинаковый ID и одинаковую подпись. Внутренние ID
навигации различаются и не переиспользуются после Reload. Существующие номера
штатных страниц/массивов не меняются. При удалении выбранной вкладки меню
возвращается к последней штатной странице.

`ui.create_tab_group(tab, id, title, column?)` возвращает ID блока. Колонка:
1 — левая, по умолчанию; 2 — правая. Без правых блоков используется вся ширина.
Блоки идут в порядке создания, длинные списки прокручиваются. Высота блоков в
NEXT GEN рассчитывается по количеству контролов и ограничивается высотой панели;
блоки используют штатный вид/скролл меню. Блоки вкладок отображаются только
в NEXT GEN. Отдельные внешние окна для вкладок не создаются.

`ui.attach_tab(control, tab?, group?)` размещает свой контрол из `ui.create`
в своей вкладке и блоке, сохраняя его на странице настроек скрипта в обоих стилях.
Без `group` используется автоматический блок с названием вкладки.
Значения, bind и `ui.get`/`ui.set` продолжают работать.
`ui.attach_tab(control, nil)` убирает дополнительное отображение во вкладке.
Привязки к вкладке и к `ui.create_window` взаимоисключающие: последняя операция
`ui.attach_tab` / `ui.attach_window` переносит контрол в выбранное место.

`ui.remove_tab(id)` удаляет свою вкладку; её контролы остаются на странице
скрипта, не удаляются и не теряют значения. Ошибка скрипта/выгрузка/Reload
автоматически освобождают все его вкладки. Новые функции не создают callbacks:
функционал пишет автор в обычных `events.on`, меню отображает retained-контролы.
Обёртки imgui/xui для собственных окон продолжают работать отдельно.

## Оформление и анимация

`ui.set_tab_style(id, options)` меняет только перечисленные поля.
`ui.set_tab_style(id, nil)` сбрасывает цвета и значок к базовым значениям,
сохраняя ID, текущее название, группы и контролы.

| Поле options | Значение |
| --- | --- |
| `title` | Собственное UTF-8 название, 1..96 байт |
| `icon` | UTF-8 строка значка, 1..16 байт; по умолчанию `>` |
| `icon_texture` | Свой handle из `render.setup_texture*` / `render.create_texture_rgba`; `0` возвращает строковый значок |
| `text_color` | Общий RGBA цвет подписи |
| `text_colors` | Массив RGBA по кодовым точкам Unicode; до 96 цветов, `{}` очищает побуквенные цвета |
| `icon_color` | RGBA tint значка или изображения |
| `background` | RGBA фона невыбранной кнопки |
| `active_background` | RGBA фона выбранной кнопки |

Все RGBA — четыре **целых** числа 0..255, включая альфу. Если цветов букв меньше,
чем букв, остаток использует `text_color`, затем базовую палитру. Пробел тоже
занимает индекс. Графемы из нескольких кодовых точек не объединяются. Для
показа символа нужен соответствующий glyph шрифта; PNG/RGBA значок от шрифта
не зависит. Текстуры здесь не загружаются автоматически по имени файла.

Анимация: обновляй цвета в `paint`, используя `client.time()`; вкладку, группы
и контролы создай один раз при загрузке. Создание текстуры разрешено только
в `paint`: подготовь её один раз и передай handle в `icon_texture`. Пример
сам рисует белый ромб с крестом в RGBA 32×32 и анимирует tint. Лимиты/владение
текстурами прежние. После выгрузки cache может удерживать ресурсы для повторного
использования, но вкладка исчезает и больше не рисуется.

## Надпись и синяя тень по буквам

Используется существующая `ui.set_style_color(backend, name, color)`:

```lua
ui.set_style_color("menu", "logo_text_1", {255, 80, 90, 255})
ui.set_style_color("menu", "logo_shadow_1", {80, 255, 140, 220})
ui.set_style_color("menu", "logo_text_2", {255, 220, 80, 255})
```

`logo_text` красит всю надпись, `logo_shadow` — всю существующую смещённую тень.
Роли `logo_text_1`…`logo_text_9` и `logo_shadow_1`…`logo_shadow_9` имеют приоритет
над общим цветом в пределах одного скрипта. Для **SKEET** индексы 1..5 — S,K,E,E,T;
для **Old Name / NEVERLOSE** доступны все девять. Тень и буква независимы; альфа
0 скрывает выбранную букву/тень. Дополнительного blur или GPU-прохода нет.
При отсутствии override используются прежние цвет текста и синяя тень.
Роли меняют NEXT GEN header; CLASSIC artwork остаётся прежним.

`ui.style_colors("menu")` включает новые роли. `nil` в `ui.set_style_color`
освобождает роль текущего скрипта. `ui.reset_theme()` освобождает **все** его
цветовые/blur overrides, включая логотип; вкладки и их собственный стиль этим
не удаляются. При конфликте скриптов последним обновлённый patch имеет приоритет,
после выгрузки открывается предыдущий patch/базовая палитра.

## Ограничения и проверка

Предел отображения — **4 кнопки суммарно, только NEXT GEN**. Превышение этого
предела скрывает лишние вкладки и не вызывает ошибку Lua. Для ограничения
расхода ресурсов сохраняются пределы регистрации: 8 вкладок на скрипт,
32 зарегистрированные одновременно, 16 групп во вкладке. Прежний лимит
128 контролов на скрипт общий для всех размещений. ID: 1..80 UTF-8 байт;
названия: 1..96; `##`, NUL, переносы и табуляция запрещены. Неизвестные поля,
чужие ID/текстуры, дубликаты, неверный цвет/колонка/лимит возвращают обычную Lua
ошибку. `ui.set_tab_style` сначала проверяет копию и применяет изменения целиком.
Создание/изменение/привязка допустимы при загрузке и из обычных callbacks,
внутри прежних бюджетов и блокировок API. Автоматически запускать другой скрипт
или обходить подтверждение активации эти функции не позволяют.

Офлайн: `python -B tools/verify_lua_menu_tabs.py`, `python -B tools/verify_lua_api.py`.
Они не компилируют проект и не выполняют игровую DLL. После пользовательской
сборки проверить клики, колесо/скролл, обе колонки NEXT GEN, длинный UTF-8 текст,
RGBA/PNG значки, закрытие меню, предупреждение активации/редактор поверх вкладки,
несколько скриптов с одинаковыми ID, выгрузку выбранной вкладки и возврат цветов.
Проверить пять и более вкладок: видны только четыре, остальные Lua работают,
после выгрузки видимой появляется следующая. В CLASSIC новых кнопок нет;
все настройки, включая прикреплённые к вкладке контролы, доступны на странице Lua.
Скорость кадров и живое отображение офлайн-проверками не подтверждены.
