## Обновление от 1 октября 2026

- Добавлен `api.protect`: обработка обычных ошибок Lua с traceback и локальными лимитами. Превышение общего бюджета или памяти останавливает скрипт.

- Ошибки загрузки шрифтов и текстур возвращают `nil, reason`; небезопасные пути остаются ошибкой API.
- Расширены данные `player_hurt`: `dmg_health`, `dmg_armor`, `health`, `armor`, `hitgroup`, `weapon`. Отсутствующие поля могут быть `nil`; `damage` — синоним `dmg_health`.
- При ошибке запуска или выполнения меню показывает подсказку **Edit Script → Copy log**. Ошибки запуска сохраняются в журнале, включая синтаксические ошибки.

Подробности: [расширения API](EXTENSIONS.ru.md), [пример диагностики](examples/protected_diagnostics.lua), [проверки после сборки](VALIDATION.ru.md).

### Как скопировать ошибку Lua

Выбери скрипт во вкладке конфигов, нажми **Edit Script**, затем **Copy log** в редакторе. В буфер обмена попадут текущий статус и сообщения журнала с учётом фильтров. При открытии скрипта с сохранённой ошибкой редактор показывает **Console**, выбирает **Only this script** и уровень **Debug**, чтобы сообщения ошибки были видны. Перед отправкой лога не нажимай **Clear log**.

## Первые пять минут

1. Открой вкладку конфигов. Конфиги и файлы `.lua` находятся в одном списке.
2. Нажми **New Lua script**. Откроется отдельное окно поверх меню.
3. Укажи имя, например `hello.lua`. Уже вставлен рабочий шаблон.
4. **Check** проверяет синтаксис без выполнения. **Save & run** сохраняет файл и запускает его.
5. Закрой редактор. Выбери Lua в списке: справа появятся **Enable / Disable**, **Edit Script**, **Reload script**, **Delete**, а ниже — элементы управления скрипта.
6. У включённого файла отображается `[on]`, у выключенного `[lua]`, у скрипта с ошибкой выполнения `[!]`.

Файлы лежат непосредственно в `%LOCALAPPDATA%\skeet`, рядом с `.cfg`. Можно писать их внешним редактором. Список файлов обновляется раз в секунду; исходник работающего скрипта перечитывается только при явном запуске или перезагрузке. Открытие меню не запускает скрипты. Загрузка конфига восстанавливает сохранённый список включённых Lua, как описано ниже.

При сохранении `.cfg` в него записываются список включённых Lua-скриптов и значения элементов, созданных через `ui.create`: чекбоксов, слайдеров, списков, цветов и текстовых полей. Значения привязаны к имени `.lua` и стабильному `id` элемента. При загрузке конфига скрипты вне списка выключаются, скрипты из списка включаются, а их параметры восстанавливаются. Конфиг без включённых скриптов выключает все Lua; старые конфиги без списка Lua ведут себя так же. Если скрипт переименован, удалён или изменил `id` элемента, прежнее значение к нему не привяжется; отсутствующий файл записывается как ошибка в журнале. Исходный код Lua в конфиг не входит — файлы `.lua` должны оставаться в папке скриптов.

Минимальный скрипт:

```lua
events.on("paint", function()
    render.text(30, 80, "Hello from Lua", {255, 255, 255, 255})
end)
```

## Редактор

| Действие | Результат |
|---|---|
| Save / Ctrl+S | Сохранить UTF-8 исходник; работающий экземпляр продолжает выполнять прежний код |
| Check | Проверить синтаксис без запуска и изменения работающего экземпляра |
| Save & run / Ctrl+Shift+S | Сохранить, проверить, выключить старый экземпляр, создать новый |
| Stop | Выключить экземпляр, сохранив текст редактора |
| Reload file | Перечитать исходник с диска; при несохранённых изменениях требуется повторный клик |
| Close | Закрыть редактор; при несохранённых изменениях предложит Save или Discard & close |
| Console | Сообщения `print`, `client.log` и ошибки с traceback |
| Clear log / Copy log | Очистить общий журнал / скопировать журнал и текущую ошибку |
| Find / Ctrl+F | Поиск в исходнике с переходом Next / Previous |
| Settings API | Поиск по категориям/именам реальных настроек; клик вставляет вызов `settings.get` в текст |

Поддерживаются номера строк, простая подсветка ключевых слов/чисел/строк/однострочных комментариев, выделение мышью и Shift+стрелками, двойной клик по слову, Ctrl+A/C/X/V, Ctrl+Z/Y и Ctrl+Shift+Z, Home/End, Ctrl+Home/End, PageUp/PageDown. Tab вставляет четыре пробела. Enter сохраняет отступ. Колесо прокручивает вертикально, Shift+колесо — горизонтально. Окно перемещается за заголовок и изменяет размер за нижний правый угол.

Горячие клавиши сохранения действуют при фокусе в исходнике. Delete редактирует текст, пока редактор открыт. Для закрытия редактора служит Close. Простая подсветка не анализирует многострочные Lua-строки и комментарии; это не влияет на выполнение скрипта.

## Как выполняется Lua

У каждого файла собственные глобальные переменные, callbacks, элементы меню и хранилище. Верхняя часть файла исполняется один раз при включении. Для повторяющейся работы регистрируй callback. **Не делай бесконечный цикл для ожидания кадра**.

```lua
local frames = 0
events.on("paint", function()
    frames = frames + 1
    if frames == 1 then print("First frame", api.script) end
end)
```

Lua-вызовы сериализованы: один скрипт не исполняется одновременно в двух потоках. Между файлами порядок определяется именем файла без учёта регистра; внутри файла — порядком регистрации обработчиков. Несколько скриптов могут менять одну настройку/команду: позднее изменение побеждает. Лучше делить ответственность между скриптами.

Ошибка в callback выключает этот файл, снимает его временные переопределения и очищает callbacks/меню. Другие файлы продолжают работать. При обычном выключении вызывается `shutdown`; после ошибки он не вызывается. При ошибке загрузки уже выполненные постоянные `settings.set` не откатываются. Для временного поведения используй `settings.override`.

Синтаксическая ошибка при перезагрузке оставляет прежний экземпляр работающим. Если синтаксис верен, старый экземпляр останавливается до исполнения нового; ошибка выполнения нового экземпляра оставляет файл выключенным. Не рассчитывай на сохранение локальных переменных при перезагрузке.

## Форматы данных

* Вектор: `{x = 10, y = 20, z = 30}`. Углы используют `x = pitch`, `y = yaw`, `z = roll`, в градусах.
* Цвет: `{r, g, b, a}`, четыре целых числа `0..255`. Альфа обязательна.
* Экранные координаты и размеры: пиксели окна игры, начало в левом верхнем углу.
* Массивы Lua начинаются с **1**. Combo тоже возвращает индексы с 1.
* Идентификатор игрока — индекс **контроллера**. `0` обозначает локального игрока. Это не адрес в памяти, не SteamID и не индекс pawn.
* Возвращаемые таблицы — копии. Присваивание `entity.get(id).health = 1` не меняет игру. Для изменения поведения существуют `settings.*` и `cmd.*`.
* При передаче таблиц в API нужны либо строковые ключи, либо плотный массив `1..N`. Смешанные/разреженные и циклические таблицы не поддерживаются. Пустая таблица сериализуется как объект.

## События — `events`

### `events.on(name, callback) -> id`

Подписывает функцию, возвращает целочисленный идентификатор. Callback получает одну таблицу; у командных событий и `paint` она пустая. Добавленный во время dispatch обработчик начнёт работу со следующего такого события.

### `events.off(id) -> boolean`

Удаляет свою подписку. Возвращает `true`, если подписка была активна. Можно вызвать из самого callback. Удалённые callbacks не вызываются повторно в текущем dispatch.

| name | Когда вызывается | Что доступно |
|---|---|---|
| `paint` | Каждый Present после встроенных визуалов, до меню | Рисование, экранные данные, entity-снимки, настройки |
| `create_move` | После обновления общего combat-контекста, до antiaim, movement и ботов | `cmd.*`, `combat.*`, `trace.*`, настройки |
| `pre_rage` | До захвата настроек и обработки встроенного ragebot | То же |
| `post_rage` | После встроенного ragebot | То же |
| `pre_legit` | Перед встроенным legitbot | То же |
| `post_legit` | После встроенного legitbot | То же |
| `post_move` | После ботов/movement/quickpeek, до окончательной синхронизации движения | То же; предпочтительное место для итогового изменения движения |
| `finalize_command` | После движения и ботов, перед применением позы antiaim, упаковкой кнопок и CRC | Поза AA и кнопки; изменение движения запрещено |
| `frame_stage` | В конце игрового frame-stage hook | Таблица `{stage = integer}`; без `cmd`, трассировки и combat-вызовов |
| `game_event` | В ближайшем frame-stage после события | Скопированные поля события; без доступа к живому event-указателю |
| `shutdown` | При Disable, Delete, перезагрузке или штатной выгрузке | Сохранение своего состояния; без рисования/команды |

Командные события возникают только при наличии живого локального игрока, камеры и валидной команды. В главном меню остаётся `paint`. Если встроенная логика изменит угол/кнопку после раннего callback, результат раннего изменения может быть заменён.

`game_event` получает `name`, `userid`, `attacker`. Последние два поля — индексы контроллеров или `nil`, если поле отсутствует/контроллер не найден; **локальный игрок имеет индекс `0`**. Для `bullet_impact` есть `position = {x,y,z}`. В `player_hurt` копируются `dmg_health` (также `damage`), `dmg_armor`, `health`, `armor`, `hitgroup`, `weapon`: урон, оставшиеся HP/броня, hitgroup и имя оружия из события. Поле без значения в исходном событии остаётся `nil`; `hitgroup` не является индексом кости или хитбокса. Считать урон по разнице снимков HP не требуется. Регистрируются `bullet_impact`, `round_start`, `player_hurt`, `player_death`, `weapon_fire`, `round_end`, `round_freeze_end`, `player_spawn`. Очередь хранит до 128 событий; при переполнении удаляется самое старое.

```lua
events.on("game_event", function(e)
    if e.name == "round_start" then print("New round") end
end)
```

Для счётчика своих убийств проверяй `player_death` с `attacker == 0` и `userid ~= 0`. За каждым выстрелом штатного рейджбота можно следить через `rage_shot`: событие выдаёт локальный `id` попытки, номер команды, выбранную цель и хитбокс, ожидаемый урон и hitchance, затем обновляет статус до `fired`, `hit`, `miss` или `unconfirmed`. [Поля, порядок статусов и ограничения сопоставления](RAGEBOT.ru.md#rage_shotshot--жизненный-цикл-выстрела). Панель [ragebot_info.lua](widgets/ragebot_info.lua) теперь считает команды и подтверждённые выстрелы отдельно по этим `id`; `miss` означает **оценку отсутствия события урона**, а не точный результат сервера. Счётчики живут до перезагрузки Lua; чекбокс *Reset stats each round* обнуляет их в начале раунда.

Мировой хитмаркер может взять координаты последнего локального `bullet_impact` и после `player_hurt` показать там изображение. При отсутствии недавней точки [soufiw_hitmarker.lua](widgets/soufiw_hitmarker.lua) показывает его около позиции пострадавшего игрока. Это приближение: API не выдаёт точное пересечение луча с хитбоксом, которое вычисляет штатный хитмаркер.

## Все зарегистрированные настройки — `settings`

Эта часть API подключена к тому же реестру, который сохраняет конфиги. Она охватывает зарегистрированные настройки ragebot, legitbot, movement, ESP, chams, glow, world, misc, changer и их бинды. Когда разработчик регистрирует новое поле в реестре, оно автоматически появляется в API.

Имена чувствительны к регистру. Категории и имена часто содержат пробелы. Не угадывай путь по заголовку меню: пользуйся каталогом.

### `settings.list([category_filter]) -> descriptors[]`

Настройки оружия разделены на 34 отдельных профиля. Каталог категорий возвращает
`settings.weapon_profiles()`; подробности, миграция конфигов и полный список —
[WEAPON_PROFILES.ru.md](WEAPON_PROFILES.ru.md). Например, `ragebot - awp`,
`ragebot - ssg08`, `legitbot - deagle`. Панель Settings API показывает эти категории.

Каждая запись: `{category, name, type, count, writable}`. Фильтр — подстрока категории. `count` — число элементов для boolean_array; для остальных полей обычно 1. Вызывать разумнее один раз при загрузке, а не каждый кадр.

```lua
for _, field in ipairs(settings.list("ragebot")) do
    print(field.category, field.name, field.type)
end
```

### `settings.get(category, name) -> value`

Читает текущее эффективное значение, включая override. Неизвестное имя вызывает ошибку. Для переключателей возвращает boolean; бинды читаются отдельно.

| type | Формат значения |
|---|---|
| `setting`, `boolean` | `true` / `false` |
| `integer` | Целое число в диапазоне int32 |
| `byte` | Целое `0..255` |
| `number` | Конечное число, для записи `-1000000..1000000` |
| `color` | `{r,g,b,a}` |
| `vector` | `{x,y,z}` **массив из трёх чисел**, в отличие от геометрических векторов API |
| `boolean_array` | Массив boolean строго длины `count` |
| `string` | Строка, для записи до 4096 байт |
| `custom` | Структурированный объект; поддержанные форматы ниже |

### `settings.set(category, name, value)`

Постоянно меняет базовое значение. После выключения скрипта оно остаётся. Для сохранения между запусками игры нужно сохранить конфиг обычной кнопкой Save. Если поле перекрыто override, `set` меняет его базу, а эффективное значение останется перекрытым до снятия override.

Проверяются типы, длины и числовые представления. Допустимый диапазон конкретной функции может быть уже диапазона хранения: например, hitchance — `0..100`. Соблюдай пределы соответствующего элемента меню. API не превращает недопустимый индекс материала или режима в допустимый.

### Чамсы: игроки, локальная модель, руки и оружие

Через settings доступны семь каналов чамсов. В меню выбираются Bloom/Glow; Flat остаётся доступным через Lua. Модуль chams поддерживает восемь целей, включая `attachments` — оружие локального игрока в третьем лице, как в руках, так и на модели (висящие пистолет, нож и другие отображаемые предметы его оружейного инвентаря). `chams.builtin_material` получает Bloom/Glow/Flat, `chams.create_material` создаёт плоский материал, а `chams.load_material` загружает готовый игровой VMAT по виртуальному пути `materials/.../*.vmat_c`. Смотри [API, пути и ограничения](CHAMS.ru.md), [glow при зуме с независимыми attachments](examples/scoped_local_glow.lua), [материал по пути](examples/material_path_chams.lua), [противники](examples/custom_flat_chams.lua), [руки и оружие](examples/hands_weapon_chams.lua), [локальный игрок](examples/local_player_chams.lua).

### Пример: RGB glow противников

Скопируй [rgb_esp_glow.lua](examples/rgb_esp_glow.lua) в папку Lua, включи файл и поставь галочку **RGB enemy glow** в настройках скрипта. Для переключателя точные ключи: категория `glow enemy`, имя `glow`; для цвета: категория `glow enemy`, имя `color`. Порядок аргументов: `category, name`.

```lua
local enabled = ui.create("checkbox", "my_glow", "RGB enemy glow", false)
local function update()
    if not ui.get(enabled) then
        settings.override("glow enemy", "glow", nil)
        settings.override("glow enemy", "color", nil)
        return
    end
    local t = client.time()
    local function channel(offset)
        return math.floor(127.5 + 127.5 * math.sin(t + offset))
    end
    settings.override("glow enemy", "glow", true)
    settings.override("glow enemy", "color", {
        channel(0), channel(2.0944), channel(4.1888), 90
    })
end
events.on("paint", update)
```

Полный пример также снимает overrides при выключении файла. Цвет задаётся четырьмя целыми компонентами RGBA от 0 до 255. Для других эффектов смотри [rgb_chams.lua](examples/rgb_chams.lua) и [rgb_custom_scope.lua](examples/rgb_custom_scope.lua). Точные ключи своего клиента можно вывести через `settings.list("glow")`.

### Цвета keybinds и watermark

Цвет текста встроенного списка активных биндов и надписи `skeet` доступен через Settings API. Оба поля имеют тип `color`: таблица `{r, g, b, a}` из четырёх целых чисел `0..255`. По умолчанию цвет белый.

| Элемент | Категория | Имя поля |
|---|---|---|
| Список активных биндов | `widgets` | `keybinds color` |
| Watermark `skeet` | `widgets` | `watermark color` |

```lua
settings.set("widgets", "keybinds color", {255, 80, 160, 255})
settings.set("widgets", "watermark color", {80, 200, 255, 255})
```

`settings.set` меняет базовый цвет; сохрани конфиг, чтобы он сохранился после перезапуска. Для временной анимации используй `settings.override` и снимай его через `nil`. Готовые варианты: [rgb_keybinds.lua](examples/rgb_keybinds.lua) и [rgb_watermark.lua](examples/rgb_watermark.lua).

### `settings.override(category, name, value_or_nil)`

Устанавливает временное значение, принадлежащее этому скрипту. `nil` снимает его. Выключение, удаление или ошибка скрипта снимает все его overrides автоматически.

При конфликте побеждает последний вызов override. После его снятия восстанавливается override другого скрипта, затем базовое значение. Видимое изменение пользователем под действующим override запоминается как новая база. Загрузка/сброс конфига очищает записи overrides при ближайшем Lua-dispatch; если поведение должно сохраняться, повторяй override в подходящем callback.

```lua
events.on("pre_rage", function()
    if client.key_down(0x58) then -- X
        settings.override("ragebot - ak47", "min damage", 80)
    else
        settings.override("ragebot - ak47", "min damage", nil)
    end
end)
```

Конфиг сохраняет текущие эффективные значения. Если нужно сохранить профиль без временных overrides, сначала выключи соответствующие скрипты.

### `settings.bind(category, name [, key, mode]) -> bind`

Только для `type == "setting"`. Возвращает `{key, mode, active}`. При четырёх аргументах изменяет бинд постоянно и сбрасывает накопленное состояние биндов. `key` — Windows VK `0..255`, `0` снимает клавишу. `mode`: `0` toggle, `1` hold_on, `2` hold_off. У отдельных функций, например общего переключателя legitbot, собственная логика может требовать определённый режим.

### Свой список биндов: `settings.binds()`

`settings.binds()` возвращает снимок всех штатных настроек с назначенной клавишей и Lua-чекбоксов с биндом из включённых скриптов. Каждая запись содержит `{category, name, key, mode, active, value}`; у Lua-чекбоксов `category == "lua"`. `active` показывает состояние бинда, `value` — текущее значение настройки. В ответ входят и неактивные бинды; для списка включённых обычно проверяют оба поля. Снимок не меняет настройки и может вызываться в `paint`.

Штатный список можно скрыть через `settings.override("widgets", "show keybinds", false)`. Базовое значение этого переключателя — `true`; после снятия override список снова появится. Чтобы выключить его постоянно, используй `settings.set("widgets", "show keybinds", false)` и сохрани конфиг.

Тот же переключатель теперь доступен в Misc → Keybinds перед Skeet Icon.
Он отключает только штатное отображение: обработка клавиш, `settings.binds()`,
Lua font/color overrides и собственные списки скриптов не отключаются. При
скрытии очищаются анимации строк; исчезающая строка хранит собственную копию
подписи и не читает удалённую Lua-настройку после выгрузки. Офлайн-регрессии
проверяют эти ветки и запуск/paint/shutdown примеров `rgb_keybinds.lua`,
`custom_keybinds.lua`, `most_wanted.lua` со скрытым штатным списком. Проверка
реального запуска произвольных скриптов в игре остаётся за пользователем.

```lua
events.on("paint", function()
    settings.override("widgets", "show keybinds", false)
    local y = 200
    for _, bind in ipairs(settings.binds()) do
        if bind.active and bind.value then
            render.text(100, y, bind.name, {255, 255, 255, 255})
            y = y + 20
        end
    end
end)
```

Для своего оформления используй `render.setup_font` и передай его handle в `render.text`; маркеры можно нарисовать примитивами или загрузить через `render.setup_texture` и показать через `render.texture`. Для собственных действий, которых нет в реестре настроек, проверяй клавишу через `client.key_down(vk)` и рисуй дополнительную строку. Полный пример с отключением штатного списка, шрифтом, маркерами и возвратом исходного состояния: [custom_keybinds.lua](examples/custom_keybinds.lua).

[most_wanted.lua](examples/most_wanted.lua) воспроизводит `Nine_Thou_Grant_Mohrman_Superstars_Remix_Game_Version_Clean.mp3` из `%LOCALAPPDATA%\skeet\muzon` и применяет `%LOCALAPPDATA%\skeet\fonts\nfsmw.ttf` к подписям ESP, списку keybinds и watermark. Для штатного текста есть `render.builtin_font("esp"|"keybinds"|"watermark", handle|nil)`; вызов делается в `paint`, при выключении скрипта его переопределения снимаются.

### Шрифты, изображения и графические ресурсы

Lua API читает ресурсы из папки конфигов игры, обычно `%LOCALAPPDATA%\skeet`:

| Тип ресурса | Путь на диске | Аргумент API |
| --- | --- | --- |
| Шрифт TTF/OTF | `%LOCALAPPDATA%\skeet\resources\имя.ttf` | `render.setup_font("имя.ttf", 16)` |
| Обычная текстура | `%LOCALAPPDATA%\skeet\resources\имя.png` | `render.setup_texture("имя.png")` |
| Текстура из папки изображений | `%LOCALAPPDATA%\skeet\skeetles\имя.png` | `render.setup_texture("skeetles/имя.png")` |

Передавай только имя файла, без абсолютного пути. Для шрифта используются только файлы из `resources`; для текстуры разрешены `resources` и `skeetles` с префиксом `skeetles/`. Подпапки и `..` не поддерживаются. Файл должен быть обычным файлом размером от 1 байта до 4 МиБ. Поэтому шрифт, лежащий в `%LOCALAPPDATA%\skeet\fonts`, нужно скопировать в `resources`; сам путь `fonts\...` Lua API не принимает.

`render.setup_font(filename, size)` вызывай из `paint`. Размер задаётся в пикселях и должен быть в диапазоне 6–96. Обычное имя ищется в `config_dir/resources/<filename>`; `"fonts/имя.ttf"` — в `config_dir/fonts/имя.ttf`. Функция возвращает handle шрифта или `nil, reason`, если файл отсутствует, загрузка не удалась либо исчерпан кэш. Handle передаётся последним аргументом в `render.text` и вторым аргументом в `render.measure_text`. Если передать `nil` или не передать handle, используется стандартный шрифт. `render.measure_text` возвращает ширину и высоту строки; когда нужна только ширина, достаточно `local width = render.measure_text(text, font)`. [Коды ошибок ресурсов](EXTENSIONS.ru.md#ошибки-загрузки-ресурсов).

Загружай каждый размер шрифта и каждую текстуру один раз, а не на каждом кадре. Handle принадлежит создавшему его Lua-скрипту: не передавай его другому скрипту и получай заново после перезагрузки. В одной сессии ограничено число загруженных ресурсов; одинаковые данные с одинаковым размером шрифта переиспользуются из кэша. Ошибочный размер шрифта, недопустимый файл или превышение лимита ресурсов дадут ошибку скрипта.

```lua
local font, font_loaded = nil, false

events.on("paint", function()
    if not font_loaded then
        font_loaded = true
        font = render.setup_font("Excalifont-Regular.ttf", 18)
    end

    local label = "Custom keybinds"
    local width, height = render.measure_text(label, font)
    render.text(40, 40, label, {255, 255, 255, 255}, font)
    render.text(40, 44 + height, "text width: " .. math.floor(width),
        {190, 210, 235, 255}, font)
end)
```

У `render.setup_texture` действует тот же принцип: загрузи текстуру один раз в `paint`, сохрани handle, затем рисуй через `render.texture(handle, x, y, width, height, tint)`. `render.texture_size(handle)` сообщает исходный размер, а необязательный `tint` окрашивает текстуру; белый `{255,255,255,255}` сохраняет её исходные цвета. Для вращения вокруг центра используй `render.texture_rotated`. Если файл не найден или формат не поддержан, загрузчик возвращает `nil`; проверяй handle и при его отсутствии показывай запасной вариант, например текст или примитив.

Пример [custom_keybinds.lua](examples/custom_keybinds.lua) использует `Excalifont-Regular.ttf`: положи файл в `%LOCALAPPDATA%\skeet\resources` (скрипт ищет шрифт в этой папке) и включи Lua в меню. Скрипт применяет шрифт к заголовку и названиям всех отображаемых биндов. [shaurma_hunter.lua](examples/shaurma_hunter.lua) показывает счётчик `SHAWA X N` с иконкой `shawa.png` из `%LOCALAPPDATA%\skeet\skeetles`; размер картинки меняется ползунком, а счёт убийств сохраняется в хранилище скрипта.

### Изображения вместо стрелок мануала

Положи PNG в `%LOCALAPPDATA%\skeet\skeetles`. В [manual_arrow_images.lua](examples/manual_arrow_images.lua) для левой и правой стрелок отдельно указаны `left_path` и `right_path`; сейчас оба используют `"skeetles/fluttershy.png"`. Каждый путь можно изменить независимо. Функция загружает файлы только из разрешённых папок; абсолютный путь к файлу передавать нельзя.

У каждой штатной стрелки есть отдельный Lua-переключатель: `settings.override("anti aim", "manual left arrow", false)` скрывает левую, `settings.override("anti aim", "manual right arrow", false)` — правую. Скрипт скрывает стрелку только после успешной загрузки её изображения, поэтому отсутствующий файл оставляет штатную стрелку. При выключении скрипта overrides снимаются.

Для проверки состояния мануала используй фактические ключи старых настроек: `settings.get("manual left", "anti aim")`, `settings.get("manual right", "anti aim")` и `settings.get("manual arrows", "anti aim")`. Расстояние читается через `settings.get("anti aim", "manual arrow distance")`. Пример рисует изображения по обе стороны центра экрана только при соответствующем направлении мануала.

### Перетаскиваемое изображение

[draggable_image.lua](examples/draggable_image.lua) загружает `skeetles/logo.png` из `%LOCALAPPDATA%\skeet\skeetles` и рисует его в исходном размере, полученном через `render.texture_size`. Путь и начальные координаты можно изменить в скрипте; положение после перетаскивания сохраняется через `storage.set`.

Чтобы вращать изображение вокруг центра, используй `render.texture_rotated(handle, center_x, center_y, width, height, angle)`. Угол измеряется в радианах; `client.time() * speed * 2 * math.pi` задаёт `speed` оборотов в секунду. При скорости 0 изображение стоит на месте. В загруженном `ezo 1x1.lua` этот вызов управляется отдельным слайдером скорости.

Есть ещё пять самостоятельных скриптов: [draggable_fluttershy.lua](examples/draggable_fluttershy.lua) для `fluttershy.png`, [draggable_nlcrack.lua](examples/draggable_nlcrack.lua) для `nlcrack.png`, [draggable_soufiw_beta.lua](examples/draggable_soufiw_beta.lua) для `soufiw beta.png`, [draggable_soufiw_original.lua](examples/draggable_soufiw_original.lua) для `soufiw original.png` и [draggable_twilight.lua](examples/draggable_twilight.lua) для `twilight.png`. Все файлы ищутся в `%LOCALAPPDATA%\skeet\skeetles`; пробелы в именах `soufiw beta.png` и `soufiw original.png` обязательны. У каждого скрипта собственный переключатель, слайдер размера в процентах, начальная позиция и ключи сохранения координат. Масштабирование сохраняет пропорции изображения, а положение каждого сохраняется независимо.

[priora.lua](examples/priora.lua) показывает `image_2305.png`, а [radar.lua](examples/radar.lua) — `196345.png` из той же папки. У них такие же отдельные слайдеры масштаба и независимое сохранение позиции. Если старый скрипт рисует прямоугольное изображение квадратом, используй `render.texture_size(handle)` и вычисляй высоту как `width * original_height / original_width`.

`ui.mouse_state()` доступен в `paint` и возвращает `{x, y, down, clicked}` в экранных пикселях. Ввод обновляется перед Lua-callbacks текущего кадра: `clicked` означает новое нажатие ЛКМ в этом кадре, `down` — удержание. Начинай перетаскивание по `clicked` внутри области элемента, затем перемещай его по координатам мыши, пока `down == true`; сохраняй смещение от точки захвата, чтобы элемент не прыгал к курсору. Начинай и продолжай перетаскивание только при `ui.is_menu_opened() == true`. При отпускании ЛКМ или закрытии меню прекращай перенос и сохраняй координаты. Все callbacks одного кадра видят один и тот же клик; чтение `ui.mouse_state()` его не расходует.

### Проверенные имена combat-настроек

Общие ragebot: категория `ragebot`, имена `enabled`, `no spread`, `auto scope`, `ragebot information`, `randomize scales`, `extrapolation ticks`. Для каждой группы оружия доступен `lethal b-aim`. Полный список смотри через `settings.list`.

Каждое оружие имеет отдельную категорию: `ragebot - ak47`, `legitbot - awp` и т. п. Все 34 ключа возвращает `settings.weapon_profiles()`. Старые классы `pistol`, `smg`, `rifle`, `shotgun`, `sniper`, `lmg` поддерживаются как совместимые псевдонимы; запись через них применяется ко всему классу. Правила чтения и импорта старых конфигов описаны в [WEAPON_PROFILES.ru.md](WEAPON_PROFILES.ru.md).

Для rage-группы зарегистрированы `silent`, `force b-aim`, `lethal b-aim`, `max fov`, `hit chance`, `min damage`, `min damage bind`, `bind min damage`, `body scale`, `head scale`, `dynamic scale`, `hitboxes`, `autostop`. `hitboxes` содержит шесть флагов; `autostop` — `{quick_stop, between_shots}`. Порядок hitboxes соответствует пунктам соответствующего меню.

Для legit-групп не копируй названия rage-полей: сначала выполни `settings.list("legitbot")`. Имена сохраняют совместимость с существующими конфигами, поэтому могут отличаться от видимого текста элемента.

### Changer: custom-объекты

`settings.get("changer", "agents")` возвращает `{ct = definition_index, t = definition_index}`. Для записи передай оба целых значения `0..32767`.

`settings.get("changer", "applied skins")` возвращает таблицу со **строковыми** ключами item definition index. Каждое значение — `{p = paint_kit_id, w = wear, s = seed, t = stattrak}`: `p` неотрицательный int32, `w` от 0 до 1, `s` от 0 до 1000, `t` boolean. `set` заменяет всю карту, поэтому сначала прочитай текущую и измени нужный элемент. Применение выполняет обычный changer в своих игровых hooks; это не выдача предметов серверным инвентарём.

```lua
local skins = settings.get("changer", "applied skins")
skins["7"] = {p = 180, w = 0.03, s = 42, t = false}
settings.set("changer", "applied skins", skins)
```

## Команда игрока — `cmd`

Эти функции работают только внутри командных событий из таблицы выше. Команда принадлежит движку и не выдаётся как указатель. Все изменения должны завершиться до возврата из callback.

### `cmd.get() -> command`

Снимок `{number, tick, buttons, forward, side, up, angles}`. `buttons` — целочисленная битовая маска, `angles` — `{x,y,z}`. Движение нормализовано в пределах `-1..1`. В `finalize_command` поле `angles` показывает запрошенную позу AA, если она активна; команда движения и история выстрела ещё не изменены.

### `cmd.set_angles(angles [, visible = false])`

В `finalize_command` задаёт позу AA для финального прохода: сохраняет движение и не поворачивает камеру (включая `visible=true`). На командах атаки, использования и броска гранаты поза не применяется, история выстрела не меняется. На воздушных командах без выстрела AA использует фиксированный разворот на 180° и согласует углы `input_history` с позой; запрошенные spin, jitter и Zero Pitch в полёте не применяются ради совместимости со стрейфером. На земле произвольный yaw применяется с компенсацией движения, а при нестандартном subtick-потоке может быть пропущен.

В остальных событиях записывает углы команды и shot history, обнуляет прежние угловые subtick-дельты. Pitch ограничивается `-89..89`, yaw нормализуется, roll обнуляется. `visible=true` также поворачивает локальную камеру через input-систему. После `pre_rage` запись углов блокируется на командах атаки/использования, чтобы сохранить рассчитанный выстрел. Для собственного прицеливания используй `create_move` или `pre_rage`; для AA — `finalize_command`.

### `cmd.set_movement(forward, side [, up = 0])`

Записывает нормализованное движение, ограничивая каждый компонент `-1..1`, согласует directional buttons и заменяет прежние аналоговые subtick-импульсы. Input-система затем синхронизирует движение. В текущем input layout положительный `side` соответствует движению вправо. Используй `create_move` или `post_move`. В `finalize_command` эта функция выдаёт ошибку: там синхронизация движения уже завершена.

### `cmd.set_button(mask, pressed)`

Устанавливает/снимает указанные биты, обновляет changed-mask. `pressed` должен быть boolean. Финальная синхронизация и CRC выполняются C++ input-системой.

Таблица `buttons`: `attack`, `jump`, `duck`, `forward`, `back`, `use`, `moveleft`, `moveright`, `attack2`, `reload`, `speed`, `zoom`, `score`, `inspect`.

```lua
events.on("post_move", function()
    local me = entity.local_player()
    if me and me.alive and client.key_down(0x20) then
        cmd.set_button(buttons.jump, (me.flags & 1) ~= 0)
    end
end)
```

API не заставляет сервер принять команду. Задержки оружия, игровые ограничения и прочая встроенная логика продолжают действовать. Это доступ к текущей команде, а не произвольное изменение серверного состояния.

## Игроки, предметы и оружие — `entity`

### `entity.local_player() -> player | nil`

Снимок локального игрока с `id=0`, либо `nil` вне игры/без pawn.

### `entity.players([enemies_only = false]) -> player[]`

Список доступных игроков. `true` оставляет живых противников и исключает локального игрока. Пустой список вне матча — нормальная ситуация.

### `entity.get(id) -> player | nil`

Повторно разрешает controller id. Игровые индексы могут переиспользоваться: не сохраняй их как вечную идентичность игрока между раундами/картами.

Поля player: `id`, `name`, `health`, `alive`, `team`, `enemy`, `origin`, `velocity`, `flags`, `armor`, `scoped`. `scoped` — boolean состояния зума, `false` при недоступных данных. Origin/velocity — именованные векторы. Health/armor и прочие значения — доступные клиенту данные на момент чтения, не серверная гарантия актуальности.

### `entity.bone(id, bone_index) -> vector | nil`

Мировая позиция кости. Индекс `0..127`, при отсутствии pawn/cache/кости возвращается `nil`. Это индекс кости модели, а не hitbox index. Константа головы в этом проекте — `cstypes::bone_ids::head = 7`; у другой модели проверяй соответствие.

### `entity.bounds(id) -> {x,y,w,h} | nil`

Экранный bounding box игрока. Если проекция недоступна, возвращает `nil`. Подходит для `paint`.

### `entity.weapon(id) -> {item_id, ammo, reloading} | nil`

Текущее оружие игрока. Для локального используй `entity.weapon(0)`.

### `entity.items() -> item[]`

Снимки предметов из существующего item-cache: `{id, class_hash, origin}`. Это не перечисление абсолютно всех сущностей движка. Item-id нельзя передавать в функции для игроков. `class_hash` — hash имени класса, origin — мировая позиция.

## Combat и трассировка

Все функции этого раздела требуют командный callback. Не вызывай их из `paint` или при загрузке файла.

### `combat.context() -> context`

Возвращает `{valid, weapon_type, item_id, tick, time, spread, inaccuracy, scoped, range, eye}` из общего combat-контекста. `eye` — текущая расчётная точка выстрела. Сначала проверяй `valid`. `time` — игровое время, не `client.time()`.

### `combat.can_shoot() -> boolean`

Использует штатную проверку готовности оружия для текущей команды.

### `combat.aim_punch() -> angles | nil`

Отдача локального игрока в углах; `nil` при отсутствии pawn.

### `combat.damage(target_id, world_point [, record_tick]) -> result | nil`

Расчёт попадания штатной penetration-системой для текущего оружия и текущего положения цели. `result = {damage, hitbox, hitgroup, penetrated}`. `nil`, если цель/оружие недоступны или расчёт не нашёл попадание. Это прогноз, а не подтверждённый урон. Расчёт использует текущую позу, а не автоматически выбранную историческую запись.

В v2 необязательный `record_tick` выбирает доступную историческую запись; если её уже нет, возвращается `nil`. Без аргумента поведение прежнее.

### `combat.records(target_id) -> record[]`

До 64 валидных lagcomp-записей в порядке хранения: `{tick, time, origin, velocity, ducked, extrapolated}`. Таблицы являются копиями. Они не позволяют напрямую применять/перезаписывать внутренний bone-cache.

### `trace.line(start, finish [, skip_player_id = 0]) -> result`

Луч со штатной маской `0x1c3003` и collision layer 4. Возвращает `{fraction, end_pos, normal, all_solid}`. `fraction` близкое к 1 означает, что луч прошёл до конца. `skip_player_id` — игрок, которого нужно исключить; по умолчанию локальный.

Тяжёлые расчёты выполняй для выбранных точек/целей, а не для сотен вариантов в каждом callback. Бюджет Lua не может прервать уже начатый нативный расчёт внутри движка.

## Рисование — `render`

Рисующие функции разрешены **только в `paint`**. Они добавляют примитивы в нижний слой, после встроенных визуалов и под меню. Каждое изображение нужно рисовать заново в каждом кадре. Измерение текста и проекция не требуют рисующего callback, но обычно используются там же.

| Функция | Аргументы и результат |
|---|---|
| `render.text(x, y, text, color [, font])` | Текст стандартным или загруженным шрифтом |
| `render.line(x1, y1, x2, y2, color [, thickness=1])` | Линия, толщина ограничивается `0.1..100` |
| `render.rect(x, y, width, height, color [, filled=false])` | Контур либо заполненный прямоугольник |
| `render.circle(x, y, radius, color [, filled=false])` | Окружность/круг, 64 сегмента, радиус `0..10000` |
| `render.measure_text(text) -> width, height` | Размер текста в пикселях |
| `render.world_to_screen(vector) -> x, y, on_screen` | Проекция; возвращает один `nil`, если камера недоступна или точка за камерой |

Проверяй `x ~= nil` и `on_screen`, прежде чем рисовать мировую точку. Координаты рисования ограничиваются диапазоном ±100000, отрицательные размеры прямоугольника становятся нулём. Цвет всегда включает альфу.

## Свои элементы меню — `ui`

Элементы создаются один раз при загрузке файла и отображаются справа под действиями выбранного включённого скрипта. На Disable они удаляются. Локальные id уникальны внутри файла; совпадение id в двух разных файлах допустимо.

### `ui.create(kind, id, label, default [, min_or_options, max]) -> id`

| kind | default | Дополнительные аргументы |
|---|---|---|
| `checkbox` | boolean | Необязательная таблица бинда `{key=VK, mode=0..2}`; без неё обычный чекбокс без бинда |
| `slider` | number | `min, max`; default должен входить в диапазон, min < max |
| `combo` | Целый индекс с 1 | Массив строк options, от 1 до 512 вариантов; длинный список прокручивается |
| `color` | `{r,g,b,a}` | Нет |
| `text` | string | Нет; значение до 4096 байт |

Id: 1..80 байт, label: до 160 байт. Не создавай элементы каждый кадр: повторяющийся id — ошибка.

### `ui.get(id) -> value`

Возвращает текущее значение, включая изменения пользователя и состояние бинда. Для `hold_on` значение истинно, пока клавиша нажата; для `hold_off` — пока она отпущена. Для `toggle` нажатие переключает базовое значение чекбокса.

### `ui.set(id, value)`

Меняет значение существующего элемента. Проверяет тип и диапазон.

### `ui.bind(id [, key, mode]) -> {key, mode, active}`

Работает только с `checkbox`. Без `key` возвращает текущий бинд; с `key` назначает или меняет его (`0` снимает клавишу). `mode`: `0` — toggle, `1` — hold_on, `2` — hold_off. У чекбокса с биндом справа от названия показывается штатный значок `[-]`: нажми на него и затем нужную клавишу; Escape очищает бинд. Режим задаётся в таблице при создании или через `ui.bind`, отдельных полей в меню нет. `active` равно текущему результату `ui.get(id)`. Программное назначение через `ui.bind` тоже показывает значок бинда. Активные Lua-бинды входят в `settings.binds()` с категорией `lua`, поэтому их можно показывать в собственном списке биндов. Клавиша и режим сохраняются в конфиге вместе со значением чекбокса. При загрузке старого конфига без сведений о бинде остаются значения из Lua-кода.

```lua
local plain = ui.create("checkbox", "plain", "Without bind", false)
local bound = ui.create("checkbox", "bound", "With bind", false,
    {key = 117, mode = 0}) -- F6, toggle

events.on("paint", function()
    if ui.get(plain) then render.text(40, 80, "Plain", {255,255,255,255}) end
    if ui.get(bound) then render.text(40, 100, "Bound", {255,255,255,255}) end
end)
```

Готовый скрипт: [bind_demo.lua](examples/bind_demo.lua). Для удержания клавиши поменяй `mode` на `1` в коде или выбери **Hold on** в меню Lua.

```lua
local distance = ui.create("slider", "distance", "Distance", 250, 10, 1000)
local tint = ui.create("color", "tint", "Color", {180, 220, 255, 255})
local mode = ui.create("combo", "mode", "Mode", 1, {"Text", "Circle"})
```

## Сохранение данных — `storage`

### `storage.get(key [, default]) -> value`

Читает значение своего скрипта; при отсутствии возвращает default или `nil`.

### `storage.set(key, value_or_nil)`

Записывает JSON-совместимое значение в память; `nil` удаляет ключ. Ключ 1..128 байт, всё хранилище до 64 KiB сериализованного JSON. Изменённые данные автоматически сохраняются раз в пять секунд при работе рендера, а также при выключении/перезагрузке/штатном завершении Lua-runtime рядом со скриптом в `имя.lua.json`. При аварийном завершении процесса последние изменения могут не сохраниться. Оставшийся после сбоя `.json.tmp` нужно удалить вручную после проверки содержимого.

Элементы `ui` сохраняются при сохранении конфига и восстанавливаются по имени
Lua и стабильному id. `storage` отдельно сохраняет собственные данные скрипта;
им также можно задать начальное значение UI. Пример:

```lua
local amount = ui.create("slider", "amount", "Amount",
    storage.get("amount", 50), 0, 100)
events.on("shutdown", function()
    storage.set("amount", ui.get(amount))
end)
```

При ошибке callback `shutdown` пропускается. Если значение должно пережить такую ошибку, обновляй `storage.set` при обнаружении изменения значения заранее. Удаление `.lua` оставляет `.lua.json`, чтобы настройки можно было восстановить при повторной установке файла.

## Сервисные функции — `client`, `api`, `print`

### Игровая консоль — `console`

`console.exec(command)` ставит игровые консольные команды в очередь. Например, `console.exec("echo Hello from Lua")` или `console.exec("toggleconsole")`. Команды и значения cvar обрабатывает сама игра; действуют её ограничения, включая `sv_cheats`. Строка содержит 1–1024 байта, без NUL; несколько команд и переводы строк разрешены намеренно.

`console.print(text)` выводит текст в консоль игры с переводом строки: до 2048 байт, без NUL. Символы `%` выводятся буквально. `print(...)` и `client.log(...)` по-прежнему пишут в журнал Lua-редактора.

`console.say(text[, team_only])` отправляет один `say` или `say_team`; второй аргумент — boolean, по умолчанию `false`. Текст содержит 1–200 UTF-8 байт, без управляющих символов, кавычек, обратных слешей и `;`. Недопустимые аргументы вызывают ошибку Lua. Пределы длины и частоты сообщений на сервере остаются в силе.

Эти три функции возвращают `true`, если запрос принят в очередь, либо `false, reason`: `console_unavailable`, `queue_full`, `rate_limited`, `script_stopping`. Принятие не подтверждает исполнение команды или доставку сообщения сервером. Очередь обрабатывается в начале следующего игрового frame-stage; после вызова из `frame_stage` потребуется последующий frame-stage. Пока игра не вызывает frame-stage, запросы остаются в очереди. Лимиты: 16 ожидающих запросов на скрипт, 128 на весь Lua API, 32 принятых запроса на скрипт за секундное окно и до 32 обработанных запросов за frame-stage. Лимит относится к запросам, а строка `console.exec` может содержать несколько команд.

`console.clear_pending()` отменяет ожидающие запросы своего скрипта и возвращает их количество. Отключение, ошибка, перезагрузка и выгрузка Lua также удаляют его очередь; уже переданные движку запросы не отменяются. Новые запросы из `shutdown` возвращают `false, "script_stopping"`. Изменения игры через консоль не откатываются при выключении Lua. API не читает ответ команды или историю игровой консоли.

```lua
local ok, reason = console.exec("echo Lua console API")
if not ok then client.log_level("warning", reason) end
console.print("Progress: 100%")
console.say("Hello from Lua!", true)
```

Тестовый [chat_spammer.lua](examples/chat_spammer.lua): переключатель выключен по умолчанию, редактируемое сообщение, общий/командный чат, интервал 1–30 секунд (по умолчанию 5). Первое сообщение ждёт полный интервал; пропущенные интервалы не догоняются. Отсутствие локального игрока приостанавливает отправку; ошибка текста выводится в журнал, после исправления ввод снова используется. Скопируй файл в `%LOCALAPPDATA%/skeet/chat_spammer.lua`, включи Lua в меню и затем его checkbox *Chat spammer*.

| Функция/поле | Описание |
|---|---|
| `client.log(...)`, `print(...)` | Сообщение в журнал редактора с префиксом имени файла; таблицы отображаются как JSON |
| `client.time()` | Монотонное время в секундах, удобно для интервалов; не календарное и не игровое время |
| `client.key_down(vk)` | Состояние Windows VK `1..255`; учитывай, что пользователь может печатать в меню |
| `client.screen_size()` | Два целых: width, height |
| `client.frametime()` | Длительность последнего render-кадра в секундах; используй в `paint` |
| `api.version` | Сейчас `2` |
| `api.lua` | Версия встроенного Lua |
| `api.script` | Имя текущего файла с `.lua` |

VK: Space `0x20`, Shift `0x10`, Ctrl `0x11`, Alt `0x12`, A..Z `0x41..0x5A`, Mouse4 `0x05`, Mouse5 `0x06`.

## Границы API и ошибки

После пересборки Lua через overlay port допускается **249 одновременно активных локальных переменных на функцию**, включая главный чанк файла (раньше 200). Параметры функции и служебные локальные переменные циклов также занимают этот лимит. Завершённые блоки `do ... end` освобождают локальные слоты, поэтому общее число объявлений в файле может быть больше. Регистров на функцию по-прежнему 255; локальные переменные и временные значения выражений делят их между собой. Сложное выражение у границы может вызвать `too many registers (limit is 255)` раньше, чем будет достигнут лимит локальных переменных. Для более крупных скриптов группируй данные в таблицы, а логику — в отдельные функции. Ограничение формата описано в [исходниках компилятора Lua](https://www.lua.org/source/5.5/lparser.c.html) и [описании инструкций](https://www.lua.org/source/5.5/lopcodes.h.html).

API позволяет управлять зарегистрированными настройками, писать собственную логику обработки команд, опираться на доступные снимки сущностей и combat-расчёты, создавать визуалы и меню. **Он не экспортирует каждую внутреннюю C++-функцию**. Игровой API не экспортирует detours, прямую подмену сканирования hitboxes и произвольные schema-поля. Подключённый FFI позволяет загружать DLL и обращаться к памяти и функциям ОС. Встроенных ботов можно выключить через настройки и реализовать собственное поведение через командные callbacks.

Перед включением или перезагрузкой Lua, а также перед загрузкой конфига с включёнными скриптами, появляется окно подтверждения по центру экрана. Кнопка запуска означает, что пользователь ознакомился с исходником и принимает риск запуска стороннего скрипта; отмена не выполняет запрошенное действие. Конфиги без включённых Lua загружаются без этого окна. При применении конфига программным путём Lua автоматически не включаются. Разработчики не несут ответственности за вред, причинённый сторонними скриптами; проверяйте их перед использованием.

Скрипты работают через перечисленные API, включая игровые консольные команды `console.exec` и игровой чат `console.say`. Через FFI скрипт также может вызывать функции ОС, загружать DLL и обращаться к файлам, сети и памяти. Игровые команды могут менять настройки и состояние игры; проверяй исходник перед запуском. В меню выбора Lua показывается предупреждение о запуске недоверенных скриптов. Эти ограничения не являются антивирусной проверкой заранее установленных файлов и не защищают от ошибок в нативном коде.

Доступны базовые функции Lua и библиотеки `math`, `string`, `table`, `utf8`, а также нативный FFI. Не открыты `io`, `os`, `package`, `debug`, `coroutine`. Убраны `dofile`, `loadfile`, `load`, `collectgarbage`, `pcall`, `xpcall`; скрипт не должен перехватывать ошибку бюджета и продолжать бесконечный цикл. `require` принимает только встроенный модуль ffi/cffi; остальные Lua-файлы автоматически не загружаются. Нативные вызовы FFI не изолированы лимитами Lua. Бинарные Lua chunks не загружаются. Это исполняемые расширения внутри процесса игры, а не изолированный процесс с абсолютной защитой от всех зависаний.

Лимиты одного скрипта: исходник 512 KiB; Lua allocator 32 MiB; 128 подписок; 128 элементов меню. В обновлённой сборке один dispatch для всех обработчиков одного события ограничен 20000000 VM-инструкций и ориентиром 250 ms; загрузка — 5000 ms. Проверка инструкций происходит раз в 1000 инструкций, нативные API дополнительно проверяют время. До 262144 API-вызовов/узлов преобразования таблиц на dispatch; таблица до 4096 элементов на уровень, вложенность до 12. Лимит не включает всю память рендера/движка и не прерывает уже начатые нативные вызовы. Журнал хранит 1000 строковых записей до 2048 байт каждая.

`api.protect` теперь имеет defaults 1000000 инструкций / 25 ms и возвращает исчерпание как `false, "budget_exceeded", info`. Остаток доступен через `api.budget()` и `client.stats().budget`. Локальное исчерпание допускает повтор в пределах родителя; при scope=dispatch требуется завершить callback и продолжить в следующем событии. Полная иерархия, коды, combat.hitchance и примеры: [BUDGETS.ru.md](BUDGETS.ru.md).

Лимиты защищают игровой поток от зависания из-за бесконечного цикла или слишком частого callback. Для `rage_*` дополнительно действует общий предел 4096 вызовов и 64 ms на скрипт за одну команду. Это аварийные верхние пределы, а не допустимая нагрузка каждого кадра: 250 ms работы в `paint` всё равно вызовут заметную задержку. FFI выполняется синхронно и не делает тяжёлую работу бесплатной; ожидание прямого FFI-вызова входит в этот бюджет. Открытие устройств, загрузку файлов и подготовку буферов выполняй при загрузке, а в частых callbacks переиспользуй результат. Новые лимиты требуют пересборки скита.

| Сообщение | Что проверить |
|---|---|
| `unknown setting` | Найди category/name через Settings API или settings.list |
| `setting value has wrong type, length or range` | Boolean вместо числа, четыре компонента цвета, правильная длина массива |
| `available only in command callbacks` | Перенеси cmd/combat/trace в create_move/pre_rage/post_move и т. п. |
| `render drawing is only available in paint` | Рисуй в paint; результаты расчётов сохрани в локальных переменных |
| `Lua execution budget exceeded` | Убери цикл ожидания; сократи работу на кадр/тик |
| `not enough memory` | Не накапливай неограниченные таблицы/строки |
| `too many local variables (limit is 249)` | Сократи одновременно активные locals: таблицы, отдельные функции, блоки `do ... end`; если предел всё ещё 200, пересобери зависимость Lua |
| `too many registers (limit is 255)` | Оставь место для временных значений: уменьши число активных locals, аргументов одного вызова и сложность выражения |
| `duplicate control id` | Создавай control один раз или используй разные id |
| `Cannot create temporary file` | Проверь права/свободное место и оставшийся `.editing` после сбоя |

## Разработчику C++ и проверяющему сборку

Лимит локальных переменных меняет `skeet/vcpkg-overlay-ports/lua/increase-local-limit.patch`, подключённый в `portfile.cmake`; `port-version` поднят до 2. Патч применяется до создания C и C++ библиотек, в Debug и Release. Обновление включится только после пересборки зависимости Lua вашей обычной manifest-сборкой vcpkg; готовые старые `lua-c++.lib` сохраняют лимит 200. Макрос в настройках самого skeet не меняет уже собранную библиотеку. Не редактируй установленный `vcpkg_installed` вместо overlay port. Формат инструкций, типы регистров и проверка их переполнения сохранены.

Manifest добавляет Lua с feature `cpp`; линковка использует `lua-c++.lib` в Debug и Release. Только runtime translation unit включает Lua headers с C++ linkage и собирается с exception handling, без PCH. Это необходимо для корректного unwind C++ объектов при Lua OOM/ошибках. Не заменяй зависимость на C-версию `lua.lib` без переработки обработки ошибок.

Порядок блокировок: `config::runtime_mutex` → mutex Lua-runtime. Command-dispatch вызывается при уже взятой exclusive config-блокировке. Event listener только копирует payload в отдельную очередь; Lua вызывается позже. Не вызывай enable/disable изнутри callback и не добавляй обратный порядок блокировок. Новая нативная функция должна проверять фазу, типы, диапазоны, время жизни игровых объектов и проходить через `guarded`.

Ключи существующих конфигов не изменены: к описателю поля добавлены человекочитаемые category/name. Два поддержанных custom-поля проверяются до десериализации. Для новых custom-типов нужно добавить проверку формата в `validate`.

Проверка без сборки: `python tools/verify_lua_api.py` (понадобятся готовые Python wheels `lupa`, `tree-sitter`, `tree-sitter-cpp`). Она проверяет Lua-синтаксис примеров/деклараций, соответствие публичных имён документации, manifest/project integration и синтаксическое дерево новых C++ файлов. Дополнительно шесть примеров исполняются с тестовыми заменами API: проверяются переключатели, nil-результаты, снятие override, отображение и storage. Эти замены не проверяют нативную реализацию. Проверка **не проверяет C++ типы, линковку и работу движка**.

После ручной сборки обязательная проверка в игре: [VALIDATION.ru.md](VALIDATION.ru.md).

Справочные источники: [Lua 5.5 Reference Manual](https://www.lua.org/manual/5.5/), [закреплённый vcpkg Lua port](https://github.com/microsoft/vcpkg/tree/39344dff01c5a5a0134caf2624cdd492f05d30ea/ports/lua).
