# Внешний пример: Doom через Lua FFI

[doom.lua](doom.lua) — самостоятельный Lua frontend к обычному
`prboom_libretro.dll`. Все libretro callbacks, ввод, окно и аудио описаны
в Lua через `ffi.cdef` и `ffi.cast`. Скрипт напрямую вызывает `retro_init`,
`retro_load_game`, `retro_run` и остальные экспорты исходного движка.

**В ските нет проекта, C++-моста, встроенного движка, WAD, специальных
функций Doom или зависимости сборки от этого примера.** Скит предоставляет
общий Lua/FFI API и универсальную загрузку текстур. Одинаковая схема может
использоваться авторами других внешних приложений и библиотек.

## Файлы и запуск

Подготовленные внешние файлы:

| Файл относительно `%LOCALAPPDATA%\skeet` | Назначение |
|---|---|
| `doom.lua` | Самостоятельный Lua-скрипт |
| `doom/prboom_libretro.dll` | Обычная сторонняя библиотека движка, Windows x64 |
| `doom/prboom.wad` | Служебные данные PrBoom |
| `doom/doom1.wad` | Оригинальный бесплатный первый эпизод Doom shareware 1.8 |
| `doom/assets.json` | Источники файлов и SHA-256 |
| `doom/PrBoom-COPYING.txt` | Лицензия движка |
| `doom/README.ru.md` | Краткая инструкция внешнего примера |

Для установки из уже проверенного локального кеша:
`python -B tools/setup_doom.py`. На новом месте для первоначальной загрузки:
`python -B tools/setup_doom.py --fetch`. Закреплённые файлы сохраняются
в `tools/doom/runtime`; другой nightly вместо записанного SHA-256 не принимается.
Кеш и пример не включены в решение или DLL скита.

Используй сборку скита с общим `ffi` и `render.update_texture_pixels`.
Отдельный проект для примера собирать **не нужно**. Включи `doom.lua`,
нажми **P**, закрой меню скита, затем Esc → New Game в меню игры.
Если меню уже закрыто, P сразу передаёт управление игре. Нажатие P
при открытом меню запоминается; повторное P отменяет этот запрос.
Другие пользователи могут установить внешний набор самостоятельно; наличие
движка и WAD не требуется для обычной работы Lua/FFI в ските.

Исправление запуска 08.10: скрипт обязательно предоставляет
`RETRO_ENVIRONMENT_GET_LOG_INTERFACE` (27). В закреплённой DLL загрузка
настроек вызывает этот callback без проверки NULL; прежний пример без него
падал внутри `retro_load_game` с выполнением по адресу 0.
Исправление находится в `doom.lua`, пересборка скита для него не нужна.
Callback удерживается до окончания `retro_deinit` вместе с остальными.

Особенность Windows x64: Lua callback принимает только первые два аргумента
нативного логирования — уровень и строку формата — и игнорирует хвост `...`.
Это адаптер фиксированного префикса под Win64 ABI, а не поддержка variadic
callbacks в cffi-lua. Он не подставляет `%s`/`%d`, не читает неизвестные
аргументы и пишет максимум 64 строки предупреждений/ошибок с меткой
`[PrBoom format]`. Информационные и отладочные строки подавлены.
Основание: [передача аргументов и varargs в Win64](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170).
Такое объявление не является переносимым C-прототипом и не подходит
для произвольной платформы или полноценного printf-форматирования.

Открыт первый эпизод **Knee-Deep in the Dead**, E1M1–E1M8 и секретный E1M9.
Для всех эпизодов положи свой `doom.wad` или `doomu.wad` в ту же внешнюю папку,
выбери соответствующий пункт IWAD в элементах Lua и перезагрузи скрипт.
Полная первая часть не включена в shareware.

## Управление

| Клавиша | Действие |
|---|---|
| P | Запустить / передать управление примеру / пауза |
| W / S | Вперёд / назад |
| A / D | Шаг влево / вправо |
| Q / E, стрелки влево / вправо | Поворот |
| Ctrl / левая кнопка мыши | Стрельба |
| Space / правая кнопка мыши | Дверь / переключатель |
| Shift | Бег |
| Tab | Карта |
| 1–7 | Выбор оружия |
| Esc / Enter / стрелки | Меню игры |
| F2 / F3 | Сохранить / загрузить |

Сохранения размещаются в `doom/saves` с подпапкой IWAD, создаваемой PrBoom.
Для имени сохранения используй цифры: WASD заняты движением.
Поворот мышью пока не реализован. Размер окна и громкость задаются в UI
скрипта; окно перетаскивается за заголовок с открытым меню скита.
При открытии меню, скрытии окна и потере фокуса выполнение кадров приостанавливается.
Для продолжения нажми P. Дополнительный checkbox блокирует движение/стрельбу
игровой команды через общие Lua API; изменения движения выполняются до
финализации, в `create_move`, `pre_rage`, `post_move`.

## Как устроен пример

Lua сохраняет C-строки каталогов, IWAD и core options, пока движок их использует.
Callback окружения поддерживает необходимые каталоги, старый интерфейс options,
формат пикселей, геометрию/частоту и запрос завершения. Все семь callbacks
удерживаются до `retro_unload_game`/`retro_deinit`; затем освобождаются.
Один именованный lease предотвращает одновременную работу двух Lua-примеров
с общей глобальной памятью той же DLL.

`retro_run` вызывается синхронно из `paint`, максимум один раз за проход.
До запуска скрипт получает первый кадр для предварительного просмотра,
включая открытое меню скита. Ввод и звук в этом состоянии отключены;
после получения кадра предварительная обработка останавливается.
Если движок не выдаёт изображение за 35 вызовов, окно показывает ошибку
`No video received...`, вместо бесконечного чёрного экрана.
P зарезервирована скриптом и не передаётся в Doom. Потеря фокуса и скрытие
окна отменяют запрос запуска, сделанный при открытом меню.
Скрипт не запускает Lua в стороннем потоке и не догоняет пропущенные кадры
длинным циклом. При частоте `paint` ниже частоты движка игра может замедляться.
Нативная работа входит в обычные временные ограничения Lua: тяжёлый WAD,
медленная DLL или диск могут исчерпать бюджет. Специального исключения для игры нет.
Обновлённый скит даёт 5000 ms на загрузку и 250 ms на обработчик;
для увеличения лимитов нужна пользовательская пересборка.

Video callback копирует framebuffer в Lua-строку до окончания его срока жизни.
Общий `render.update_texture_pixels` поддерживает libretro RGB555, RGB565
и XRGB8888 little-endian (в памяти BGRX). Текстура переиспользуется, размеры
кадра и pitch проверяются. Формат вывода окна — 4:3.

Звук выводится через прямые FFI-вызовы Windows `winmm.waveOut*`.
Устройство открывается и все восемь буферов подготавливаются при загрузке,
а не при первом нажатии P в `paint`. При воспроизведении буферы
переиспользуются без повторных prepare/unprepare. Опрос включает только
нужные игре клавиши и выполняется перед очередным кадром, а не на каждом
`paint`. Это исправляет известный путь к превышению бюджета на `ui.get(gain)`
после блокирующего открытия звука. Если core меняет частоту звука во время
работы, аудио отключается до перезагрузки скрипта, без открытия устройства в `paint`.
Есть ограниченное кольцо PCM-буферов: при переполнении звук отбрасывается,
а Lua не ждёт завершения воспроизведения. Отсутствие аудиоустройства не
запрещает играть и не вызывает повторную попытку открытия на каждом кадре.
Нативные аудио-callbacks Windows в Lua не используются.

При штатном `shutdown` скрипт закрывает движок и звук. Дополнительный
`ffi.gc`-финализатор удерживает DLL/callbacks/буферы и служит путём очистки
при ошибке Lua. Это логика внешнего скрипта, а не часть C++ скита.

## Источники и пределы проверки

[doom-assets.json](doom-assets.json) содержит хеши исходных загрузок и
внешних файлов, а также PE metadata. Пример использует API libretro v1;
заголовок и callback references сохранены в `tools/doom` из commit
`c6e0fcb8325fc7969c91387f56c63433de0f1a53`. Соответствие этого commit конкретному
nightly binary не установлено. Присутствие экспортов проверено чтением PE,
а не выполнением DLL.

Офлайн: `python -B tools/verify_lua_ffi.py --external-example` проверяет
изолированность решения, общий API, синтаксис, хеши и mock-сценарии прямого
FFI frontend, включая предварительный кадр, запуск/паузу на P, запуск после
закрытия меню и отказ движка выдавать видео. Без `--external-example` проверка общего FFI не требует
скачанных игровых файлов. Нативная сборка, запуск DLL, фактический звук,
сохранения и прохождение этими проверками не подтверждаются.

PrBoom — сторонний GPLv2 движок. Его лицензия сохраняется рядом с DLL;
при распространении самой DLL нужны соответствующие исходники конкретной
сборки. Shareware-WAD неизменён; эпизоды полной версии в набор не добавляются.

Общие руководства: [FFI](../FFI.ru.md), [подробности FFI](../FFI_DETAILS.ru.md),
[расширения графики](../EXTENSIONS.ru.md). Все правила FFI для указателей,
ABI и синхронных callbacks действуют и в этом внешнем примере.
