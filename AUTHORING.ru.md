# Как писать Lua-скрипты для Skeet

Для перевода встроенного интерфейса Skeet используй [API локализации](LOCALIZATION.ru.md).
Регистрация словаря добавляет язык в **Misc → Language**. Подписи и варианты
`ui.create` остаются на языке автора скрипта; собственный выбор языка скрипт реализует сам.
Перевод основного интерфейса не меняет ID элементов или `settings.get/set`.
`ui.set_menu_font` меняет шрифт даже у стандартного языка без создания локализации.
Для собственной панели с кнопкой открытия используй [Lua-окна](WINDOWS.ru.md).
Для отдельной вкладки внутри основного меню используй `ui.create_tab`,
`ui.create_tab_group` и `ui.attach_tab`: [вкладки и буквы логотипа](MENU_TABS.ru.md).
Названия вкладок, значки и цвета меняются через `ui.set_tab_style`; пример
[RGB Lab](examples/rgb_menu_tab.lua) можно целиком скопировать в папку скриптов.
В основном меню NEXT GEN видны только **4 Lua-вкладки суммарно**; лишние скрыты,
но сами скрипты работают. В CLASSIC добавление разделов основного меню не
поддерживается. Рекомендуется делать основные настройки в самой Lua на странице
Scripts, а вкладку использовать дополнительно для более красивой визуализации.
`ui.attach_tab` сохраняет контрол и на странице Lua, поэтому настройки доступны
в CLASSIC и при скрытой пятой вкладке.

Это учебный маршрут для автора. Полные сигнатуры и типы — в
[API_INDEX.ru.md](API_INDEX.ru.md), описание игрового API — в
[README.ru.md](README.ru.md), работа с нативными библиотеками — в
[FFI.ru.md](FFI.ru.md). Читай примеры вместе с ограничениями события,
в котором вызывается функция.

## 1. Подготовка и запуск

Скрипты — самостоятельные UTF-8 файлы `.lua` непосредственно в
`%LOCALAPPDATA%\skeet`. Дополнительные ресурсы можно положить в подпапки,
но обычный `require` не загружает другие Lua-файлы. Через него доступен только
встроенный `ffi`/`cffi`. Язык — Lua 5.5; скрипты для LuaJIT или другого API
могут потребовать переноса.

Открой вкладку конфигов → **New Lua script**, введи имя, вставь код, нажми
**Check**, затем **Save & run**. Список конфигов содержит также Lua-файлы.
**Check** проверяет синтаксис, а не существование DLL или правильность всех
API-вызовов. **Save** сохраняет текст, но работающий экземпляр продолжает
исполнять прежний код. Для применения изменений используй **Save & run**
или **Reload script**. Перед запуском действует существующее подтверждение
активации скриптов. После запуска закрой редактор и проверь результат.

```lua
local enabled = ui.create("checkbox", "enabled", "My first script", true)

events.on("paint", function()
    if not ui.get(enabled) then return end
    render.text(30, 80, "Hello from Lua", {255, 255, 255, 255})
end)
```

Скопированный извне файл появляется в списке после обновления списка файлов.
Отдельная установка пакетов для обычного Lua API не нужна. Для FFI нужна
сборка скита с подключённым cffi-lua; `api.version == 2` сама по себе этого
не подтверждает. Проверяй `type(ffi) == "table"`.

## 2. Минимум языка, который нужен в примерах

Объявляй свои переменные через `local`. Значение `nil` означает отсутствие
результата или поля; `false` — обычное логическое значение. В Lua только
`nil` и `false` считаются ложными: число `0` и пустая строка истинны.
Строки соединяются через `..`, сравнение записывается `==`, неравенство — `~=`.

```lua
local count = 0
local label = "Count: " .. tostring(count)
local color = {255, 160, 80, 255}
local point = {x = 10, y = 20, z = 30}

local function increment(amount)
    count = count + amount
    return count
end

for index, value in ipairs(color) do
    print(index, value)
end
print(label, point.x, increment(1))
```

Таблица может быть массивом `{10, 20}` или объектом `{x = 10, y = 20}`.
Массивы Lua начинаются с **1**, массивы FFI — с **0**. `ipairs` проходит
последовательную часть массива до первого отсутствующего элемента;
`pairs` перебирает поля таблицы без гарантии порядка. Несколько результатов
функции записываются как `local value, reason = function_call()`.

API ожидает конкретные формы данных. Геометрический вектор — `{x,y,z}`,
цвет — массив `{r,g,b,a}` из четырёх целых 0–255. В Settings API тип `vector`
использует массив из трёх чисел `{x_value,y_value,z_value}`. Подстановка одного
формата вместо другого вызывает ошибку или даёт неподходящий результат.

## 3. Жизненный цикл и выбор события

Код верхнего уровня выполняется один раз при запуске экземпляра. Здесь
создаются элементы `ui`, подписки и небольшие постоянные данные.
`events.on` регистрирует callback; callback выполняется позднее при событии.
После Reload создаётся новый Lua state: обычные локальные переменные,
подписки и handles прежнего экземпляра не продолжают жить в новом скрипте.

| Задача | Где выполнять |
|---|---|
| Текст, изображения, геометрия меню, создание/обновление текстур | `paint` |
| Получение команды, изменение прицеливания, раннее движение | `create_move` / подходящий командный callback |
| Изменение параметров до обработки рейджбота | `pre_rage` |
| Итоговое изменение движения и subticks | `post_move`, до синхронизации движения |
| Работа с финальной позой AA и кнопками | `finalize_command`; движение/subticks здесь менять нельзя |
| Реакция на игровой event | `game_event`, с проверкой имени и доступных полей |
| Этап игрового кадра | `frame_stage`; это не командный callback |
| Очистка при обычном выключении | `shutdown` |
| Свой алгоритм/выбор рейджбота | Специальные `rage_*`; см. [RAGEBOT.ru.md](RAGEBOT.ru.md) |

Командных callbacks может не быть в главном меню, при отсутствии живого
локального игрока или валидной команды. `paint` — частый callback, но его
частота не является частотой игрового тика. Рисовать из `create_move` нельзя.
`ui.is_menu_opened`, `ui.mouse_state`, `ui.get_menu_rect` требуют `paint`:
если это состояние нужно командной логике, сохрани его в переменную в `paint`.

Несколько callbacks одного события выполняются в порядке регистрации.
Скрипты вызываются последовательно; позднее изменение одной настройки/команды
может заменить раннее. Встроенная логика также может изменить команду после
раннего callback. Подробный порядок и ограничения — в основном справочнике.

Не добавляй подписку внутри каждого `paint`: будет накапливаться число
обработчиков. Для снятия подписки используй возвращённый id и `events.off(id)`.
`client.unload()` запрашивает выгрузку после выхода из callback; чтобы
прекратить код самого callback, после вызова напиши `return`.

## 4. Элементы управления

```lua
local visible = ui.create("checkbox", "panel_visible", "Show panel", true)
local opacity = ui.create("slider", "panel_opacity", "Opacity", 220, 0, 255)
local style = ui.create("combo", "panel_style", "Style", 1, {"Compact", "Full"})
local tint = ui.create("color", "panel_tint", "Tint", {120, 190, 255, 255})
local caption = ui.create("text", "panel_caption", "Caption", "My panel")

events.on("paint", function()
    if not ui.get(visible) then return end
    local c = ui.get(tint)
    local color = {c[1], c[2], c[3], math.floor(ui.get(opacity))}
    local text = ui.get(caption)
    if ui.get(style) == 2 then text = text .. " / Full" end
    render.text(30, 110, text, color)
end)
```

`ui.create` возвращает id, а не значение элемента. Читай значение через
`ui.get(id)`, меняй через `ui.set(id, value)`. Id уникален внутри скрипта и
должен быть стабильным между Reload; id и имя файла связывают элемент
с сохранённым конфигом. Combo использует индексы **1..число вариантов**.
Элементы UI сохраняются в конфиге при его сохранении; `storage` отдельно
хранит собственные данные скрипта.

Для checkbox можно указать бинд:
`ui.create("checkbox", "my_bind", "My bind", false, {key=118, mode=0})`.
Ключ — Windows VK, режимы: 0 toggle, 1 hold_on, 2 hold_off.
Проверяй эффективное значение `ui.get`, учитывающее бинд.

## 5. Проверка отсутствующих данных

```lua
events.on("paint", function()
    local player = entity.local_player()
    if not player or not player.alive then return end
    render.text(30, 140, "Health: " .. tostring(player.health), {255, 255, 255, 255})
end)
```

Не обращайся к `player.health`, пока не проверил сам объект. Снимок сущности
не является указателем на C++ объект. Не придумывай поля таблицы: смотри
тип в каталоге API. Необязательное поле события может быть `nil`.
Координата попадания, идентификатор игрока, bone и hitbox — разные данные;
нельзя автоматически подставлять один индекс вместо другого.

## 6. Поиск настроек и временные изменения

Настройки идентифицируются точными `category` и `name`, с учётом регистра.
Не угадывай название по видимой надписи в меню:

```lua
for _, field in ipairs(settings.list("movement")) do
    print(field.category, field.name, field.type, field.writable)
end
```

`settings.get` читает эффективное значение. `settings.set` меняет базовое
значение; оно не откатывается автоматически при выключении Lua.
`settings.override` задаёт временное переопределение текущего скрипта;
`settings.override(category, name, nil)` его снимает. На выгрузке собственные
overrides удаляются. Для эффектов, действующих лишь пока включён скрипт,
обычно нужен `override`, а не `set`. Проверяй тип и `writable` дескриптора.
Не сохраняй числовые handles ресурсов в settings или storage.

## 7. Интервалы и клавиатура

Не используй бесконечный цикл ожидания. Для интервала сохраняй время:

```lua
local next_time = 0
events.on("paint", function()
    local now = client.time()
    if now < next_time then return end
    next_time = now + 1
    print("One-second update")
end)
```

`client.time()` монотонное, в секундах; это не календарь и не время сервера.
`client.key_down(vk)` возвращает удержание кнопки. Для одного действия на
нажатие сравнивай текущее значение с сохранённым предыдущим, иначе действие
будет повторяться каждый кадр. VK — код Windows, а не ASCII-символ.
Учитывай открытое меню и ввод текста. Внешние потоки нельзя использовать
для выполнения Lua callback в этом state.

## 8. Ресурсы, файлы и FFI

Изображения/шрифты загружай один раз в `paint`, проверяя `nil, reason`.
Для меняющегося кадра используй `render.create_texture_rgba` один раз
и `render.update_texture_rgba` перед рисованием. Старые handles после Reload
получай заново. Для звуков заранее вызывай `audio.preload`.

Пути ресурсов и пределы загрузчиков перечислены в
[EXTENSIONS.ru.md](EXTENSIONS.ru.md). Их правила относятся к этим API-функциям.
FFI предоставляет отдельный нативный доступ к ОС и не ограничен теми же
каталогами. Он не превращает игру в безопасную песочницу и сам не знает
интерфейс сторонней DLL. Для DLL нужны её объявления, Windows x64 зависимости
и правила владения памятью. Пошаговый пример — в [FFI.ru.md](FFI.ru.md).

## 9. Сохранение и очистка

```lua
local launches = storage.get("launches", 0) + 1
storage.set("launches", launches)
print("Launches:", launches)
```

`storage` хранит JSON-совместимые значения отдельно для каждого имени Lua.
`nil` в `storage.set` удаляет ключ. Не сохраняй userdata, callbacks или DLL
handles. Данные пишутся периодически и при обычной выгрузке; авария процесса
может потерять последние изменения. Если данные должны пережить ошибку
callback, обновляй `storage` заранее: `shutdown` после такой ошибки пропускается.

При нормальной выгрузке прекращай нативную работу в `shutdown`. Для FFI-ресурса
добавь подходящий финализатор и удерживай DLL до последнего её вызова.
Очистка должна выдерживать повторное обращение или иметь явный признак
«уже освобождён». Рабочий поток DLL должен закончить использование буфера
до освобождения буфера Lua; это договор интерфейса DLL, а не автоматика FFI.

## 10. Ошибки, производительность и отладка

```lua
local ok, reason, value = api.protect(function()
    return 2 + 3
end)
if ok then print("Result:", value) else client.log_level("error", reason) end
```

`api.protect` возвращает `success, reason, ...results`, сохраняя несколько
результатов. Он обрабатывает обычные Lua/API-ошибки с traceback; исчерпание
общего бюджета/памяти не превращается в разрешение продолжать работу.
Обычные `pcall` и `xpcall` не предоставлены. Ошибки указателей и аварии DLL
через `api.protect` не становятся безопасными.

Не выполняй в частом callback сканирование всех настроек, загрузку файла,
создание новых шрифтов/текстур или большие вложенные циклы. Кэшируй неизменные
данные. Счётчики `client.stats()` помогают увидеть инструкции, вызовы,
время и Lua-память, но не измеряют всю память DLL, GPU и движка.

| Симптом | Что проверить |
|---|---|
| Lua отсутствует в списке | `.lua`, UTF-8 файл в корне `%LOCALAPPDATA%\skeet` |
| После Save поведение прежнее | Выполнить Save & run / Reload |
| `attempt to index a nil value` | Проверить объект/результат до чтения поля |
| `available only in paint` | Перенести вызов в `paint`, передать данные через свою переменную |
| `available only in command callbacks` | Выбрать командное событие; проверить, что игрок жив |
| `unknown setting` | Найти category/name через `settings.list` |
| Ошибка значения combo | Индекс начинается с 1 |
| Budget/memory error | Уменьшить работу callback и накопление данных |
| FFI отсутствует | Нужна новая сборка, проверить глобальный `ffi` |
| DLL не загружается | Путь, x64, зависимости, имя DLL и текст ошибки |
| Lua выключился после ошибки | Edit Script → Copy log; обычный shutdown мог не выполниться |

Для отчёта об ошибке приложи имя Lua, исходник или минимальный пример,
версию сборки, полный **Copy log**, способ повторения и требуемые ресурсы.
Сообщение «не работает» без этих данных не показывает, какая стадия не прошла.

## 11. Полная карта возможностей

| Модуль | Что позволяет | Где смотреть |
|---|---|---|
| `events` | Подписки и их снятие, события игры и callback pipeline | Основной справочник |
| `ui` | Свои элементы управления, бинды, состояние/геометрия меню | Основной справочник, расширения |
| `settings` | Каталог, чтение, запись, overrides и бинды настроек | Основной справочник |
| `entity` | Снимки игроков/предметов/оружия, кости и экранные bounds | Основной справочник |
| `cmd` | Углы, движение, кнопки, subticks и history в разрешённых фазах | Основной справочник, каталог API |
| `movement` | Контекст и передача управления bhop/strafe Lua | [MOVEMENT.ru.md](MOVEMENT.ru.md) |
| `combat`, `trace` | Доступные combat-запросы и трассировка | Основной справочник, расширения |
| `ragebot` | Callback-алгоритмы, точки и выбор попадания | [RAGEBOT.ru.md](RAGEBOT.ru.md) |
| `render` | 2D/3D графика, шрифты, изображения и изменяемые кадры | [EXTENSIONS.ru.md](EXTENSIONS.ru.md) |
| `audio` | Предзагрузка и воспроизведение разрешённых WAV/MP3 | Расширения |
| `chams` | Материалы и выбор целей | [CHAMS.ru.md](CHAMS.ru.md) |
| `models` | Выбор доступной кастомной модели | [MODELS.ru.md](MODELS.ru.md) |
| `storage` | Собственные сохраняемые данные | Основной справочник |
| `console` | Очередь игровых команд, печать, игровой чат | Основной справочник |
| `client`, `api` | Время, VK, журнал, статистика, защита и выгрузка | Основной справочник, расширения |
| `math` | Стандартная библиотека и дополнительные геометрические функции | Расширения, каталог API |
| `ffi` | C-типы, вызовы DLL, память и нативные интерфейсы | [FFI.ru.md](FFI.ru.md) |

Карта показывает доступные модули, а не обещает экспорт каждого внутреннего
метода движка. Для точного вызова сверяй сигнатуру, фазу, тип результата,
поведение при `nil` и ограничения. Полный список публичных имён приведён
в [каталоге API](API_INDEX.ru.md).
