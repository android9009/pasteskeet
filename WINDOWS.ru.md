# Свои окна Lua и отдельные клавиши

Основное меню Skeet по умолчанию переключается Delete. Окно Lua может следовать
за ним или открываться независимо, по любой выбранной VK-клавише/кнопке мыши.
Элементы, созданные через `ui.create` без переноса в окно, сохраняют прежнее
размещение в Config выбранного скрипта.

## Вместе со Skeet

```lua
local window = ui.create_window("main", "My settings") -- key=0 by default
local enabled = ui.create("checkbox", "enabled", "My feature", false)
ui.attach_window(enabled, window)
```

Окно появляется вместе со Skeet. Закрытие крестиком скрывает его до следующего
открытия Skeet; `ui.set_window_open(window, true)` может вернуть его, если Skeet открыт.
Готовый пример: [following_menu.lua](examples/following_menu.lua).

## По своей клавише

```lua
local window = ui.create_window("main", "My settings", {
    key=0x75, -- F6; 0x2D=Insert, 0x24=Home
    x=140, y=120, width=320, height=340,
})
local enabled = ui.create("checkbox", "enabled", "My feature", false)
ui.attach_window(enabled, window)
```

F6 переключает только это окно. Оно работает при закрытом Skeet и не открывает
основное меню. Повтор при удержании клавиши не переключает окно многократно.
Смена клавиши: `ui.window_bind(window, 0x24)`; возврат к следованию Skeet:
`ui.window_bind(window, 0)`. Программное открытие/закрытие:
`ui.set_window_open(window, true)`; закрытие — `ui.set_window_open(window, false)`.
Готовый пример: [independent_menu.lua](examples/independent_menu.lua).

Используются коды Windows Virtual-Key: клавиатура 1–255; мышь — 1=LMB,
2=RMB, 4=MMB, 5=Mouse4, 6=Mouse5. 0 обозначает синхронизацию, а не отдельную
клавишу. Общие Shift/Ctrl/Alt принимают обе стороны; можно указать отдельный
левый/правый код. Одинаковая клавиша переключает все окна, которым она назначена.
Если Lua явно назначил Delete, эта клавиша управляет Lua-окнами и не переключает
Skeet до снятия привязки/выгрузки скрипта. По умолчанию Delete остаётся за Skeet.
Кнопка-триггер переключает окно и при клике по его содержимому, поэтому для
интерактивных элементов обычно удобнее клавиатура или боковая кнопка мыши.

## Ввод и жизненный цикл

Интерактивное открытое окно получает курсор. Пока открыто основное меню или
независимое Lua-окно, игра не получает новые нажатия/движения мыши, а команды
движения/стрельбы очищаются по существующему механизму Skeet. `paint` и UI
продолжают работать; Lua command callbacks и боевые/двигательные функции
пропускаются до закрытия интерфейса. Матч и физика продолжаются.

Клавиша окна не передаётся игровому обработчику; отпускания проходят, чтобы
предыдущие игровые кнопки не оставались зажатыми. Во время ввода текста,
редактирования числового значения, назначения бинда, работы редактора Lua
или подтверждения запуска клавиши окон временно не переключают окна.
Закрытие последнего окна при закрытом Skeet возвращает обычное управление
и прежнее состояние курсора. В перекрывающихся Lua-окнах мышь получает верхнее;
клик поднимает окно. Редактор и подтверждение запуска имеют приоритет над ними.

При выгрузке/ошибке скрипта его окна и привязки удаляются. Количество — до 8 окон
на скрипт; общий предел элементов `ui.create` остаётся 128. Прикрепить можно только
свой элемент к своему окну. `ui.attach_window(control_id, nil)` возвращает элемент
в Config. Подписи, варианты выбора и заголовки окна сохраняют язык автора;
локализация и общий шрифт Skeet к ним не применяются.

Значения элементов/их feature-бинды сохраняются с конфигом по прежним ID.
Геометрия, клавиша открытия и состояние окон задаются Lua и не записываются
автоматически в `.cfg`: для своих настроек используй `storage.get/set`.
Например, можно передать `key=storage.get("menu_key", 0x75)` при создании.

## API

Функции доступны при загрузке и из callbacks; `paint` не обязателен.

| Функция | Результат |
| --- | --- |
| `ui.create_window(id, title, options?)` | ID нового окна |
| `ui.attach_window(control_id, window_id?)` | nil; перенос или возврат в Config |
| `ui.window_bind(id, key?)` | `{key, open, follows_menu}`; чтение/смена клавиши |
| `ui.set_window_open(id, open)` | nil; установка состояния |
| `ui.get_window(id)` | `{id, title, key, open, follows_menu, x, y, width, height}` |

`options`: `key` 0–255; `open` по умолчанию true в синхронном режиме и false
для отдельной клавиши; `x/y` по умолчанию 120/120, конечные числа по модулю ≤100000;
`width` 180–1600 (320 по умолчанию), `height` 120–1600 (360).
Окно можно перетаскивать/изменять мышью; после отрисовки геометрия ограничивается
видимой областью экрана. ID/заголовок — непустой UTF-8, до 80/160 байт.
Неизвестные/повторные ID, неверные типы, диапазоны и превышение лимита вызывают Lua-ошибку.

`open` в чтении — фактическая видимость. В синхронном режиме закрытый Skeet
скрывает окно независимо от `ui.set_window_open`. Назначение отдельной клавиши
сохраняет текущую видимость; назначение 0 возвращает следование Skeet.

После ручной сборки проверь F6 при открытом и закрытом Skeet, удержание клавиши,
мышь/перетаскивание/resize/scroll, клавиши-модификаторы, текстовые поля, два окна
на одной клавише, наложение окон, закрытие крестиком, unload/error и возврат
управления/курсора. Проверка новых функций: `python -B tools/verify_lua_windows.py`;
проверка игрового маршрута ввода: `python -B tools/verify_menu_input.py`.
Офлайн-проверки не заменяют проверку собранной DLL в игре.
